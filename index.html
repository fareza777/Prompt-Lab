The Complete Guide to Prompt Engineering in 2026

If you're learning how to create a prompt that consistently produces the best results, this guide is for you. Prompt engineering is the skill of communicating effectively with AI models. Whether you're using ChatGPT, Claude, Gemini, or any other LLM, how you phrase your request dramatically affects the quality of the output.

Why Prompt Engineering Matters

The same AI model can give you a mediocre paragraph or a brilliant, structured response — the difference is the prompt. Good prompts lead to:

  • Better accuracy — the AI understands exactly what you want
  • Consistent quality — reliable outputs every time
  • Time savings — fewer back-and-forth iterations
  • Professional results — content you can actually use

The 5-Part Prompt Structure

Every great prompt follows a basic structure. Think of it as a recipe:

1. Role

Tell the AI who it should be. This sets the expertise level and perspective.

You are a senior content strategist with 10 years of experience in B2B SaaS marketing.

2. Context

Provide background information the AI needs to understand your situation.

I'm launching a new AI writing tool targeted at freelance writers. Our main differentiator is the domain-specific templates.

3. Task

Be specific about what you want the AI to do. Use action verbs.

Write 5 LinkedIn post ideas that highlight our template feature. Each post should be 150-200 words, conversational, and end with a CTA.

4. Constraints

Set boundaries: tone, length, format, what to avoid.

Tone: friendly but professional. Avoid jargon. Don't use more than 2 emojis per post. No hashtag overload.

5. Format

Specify the output structure you need.

Return as a numbered list. Each item should have: a hook line, the body, and the CTA in bold.

Advanced Techniques

Chain-of-Thought (CoT)

Ask the AI to think step-by-step before giving the answer. This dramatically improves reasoning tasks.

Think step-by-step before answering. First analyze the data, then identify patterns, then give your recommendation.

Few-Shot Learning

Give the AI 2-3 examples of what you want. This is the fastest way to teach it your style.

Here are 2 examples of the output I want:

Example 1: [your example]
Example 2: [your example]

Now generate a new one following the same pattern.

Output Iteration

Don't try to get the perfect result in one shot. Use follow-up prompts to refine:

Good, but make it more conversational. Shorten the paragraphs. Add a specific example for the second point.
💡 Pro Tip: Use PromptLab's Readiness Score to check if your prompt has all 5 components. The score tells you exactly what's missing — Context? Constraints? Format?

Common Mistakes to Avoid

  • Being too vague: "Write me something about marketing" vs "Write a LinkedIn post about why short-form video outperforms static images for B2B brands"
  • Too many instructions: Break complex requests into smaller steps
  • No examples: Show, don't just tell. Examples are worth 1000 words of instruction
  • Ignoring output format: Always specify how you want the result structured

Putting It All Together

Here's a complete prompt using the 5-part structure:

# Role
You are a copywriter specializing in SaaS landing pages.

# Context
I'm building a landing page for PromptLab, a free AI prompt workspace. The target audience is marketers and content creators who struggle with writing effective prompts for ChatGPT and Claude.

# Task
Write the hero section copy for the landing page, including:
- A headline (max 8 words)
- A subheadline (max 25 words)
- A primary CTA button text (3-5 words)

# Constraints
- Tone: confident, clear, slightly playful
- No buzzwords like "revolutionary" or "game-changing"
- Focus on the pain point (bad prompts = bad AI output)

# Format
Return as:
**Headline:** ...
**Subheadline:** ...
**CTA:** ...

ChatGPT vs Claude: How to Write Prompts for Each

ChatGPT and Claude are the two most popular AI assistants — but they respond very differently to the same prompt. Understanding these differences is the key to getting better results from both.

The Core Difference

ChatGPT (GPT-4o) tends to be more creative, verbose, and eager to please. It follows instructions literally and produces longer outputs by default.

Claude (Sonnet/Opus) is more careful, nuanced, and prefers structured instructions. It excels at following complex multi-step instructions and maintaining context.

Prompting for ChatGPT

ChatGPT works best with:

  • Direct, action-oriented instructions: "Write 5 variations of..."
  • Role-playing: "Act as a senior developer reviewing code"
  • Delimited input: Use triple backticks for code or data
  • Explicit format requests: "Return as a markdown table"
You are a social media expert. Write 5 Instagram captions for a fitness app launch. Each caption should include:
- A hook in the first line
- 3-4 value points
- A CTA with emoji
- 5 relevant hashtags
Tone: energetic, motivational, Gen Z friendly.

Prompting for Claude

Claude responds better to:

  • Structured sections: Use headers (# Role, # Context, etc.)
  • XML tags: Claude is trained to respect XML boundaries
  • Detailed constraints: Claude excels at following complex rules
  • Examples: Few-shot works exceptionally well with Claude

You are a content strategist. Analyze the following blog post and suggest 3 improvement areas.



[Paste your blog post here]



For each improvement:
- What needs to change and why
- A specific rewrite suggestion
- Impact level: High / Medium / Low

Quick Reference

  • Creative tasks: ChatGPT tends to be more inventive
  • Analytical tasks: Claude tends to be more thorough
  • Long conversations: Claude maintains context better
  • Code generation: Both are excellent; Claude is more careful
  • Structured output: Claude follows format instructions more precisely

10 Prompt Templates Every Marketer Needs

Knowing how to create the best prompt for marketing is the difference between AI copy that sounds robotic and copy that actually converts. Here are 10 battle-tested templates you can copy, paste, and customize in PromptLab.

1. Social Media Caption

Write 5 Instagram captions for [product/announcement].
- Hook line (attention-grabbing)
- 3 value points
- CTA with emoji
- 5 hashtags
Tone: [brand voice]

2. Email Subject Lines

Generate 10 email subject lines for [campaign purpose].
Include: 3 curiosity-based, 3 urgency-based, 2 benefit-driven, 2 personalized.
Keep under 50 characters each.

3. Blog Outline

Create a detailed blog outline for: [topic]
Target audience: [audience]
Goal: [awareness/consideration/conversion]
Include: title, introduction hook, 5-7 H2 sections with bullet points, conclusion with CTA.
Word count target: [X] words.

4. Ad Copy (Facebook/Google)

Write 3 variations of ad copy for [product].
Headline (max 40 chars), primary text (max 125 chars), description (max 30 chars).
Each variation targets: 1) pain point, 2) benefit, 3) social proof.
CTA: [shop now / learn more / sign up]

5. Landing Page Hero

Write a landing page hero section for [product].
- Headline: max 8 words, punchy
- Subheadline: max 25 words, explain the value
- Primary CTA: 3-5 words
- Secondary CTA: "See How It Works"
Tone: [professional / playful / authoritative]

6. Newsletter Introduction

Write a newsletter intro for this week's edition.
Main topic: [topic]
Key takeaway: [one sentence]
Tone: conversational, like writing to a friend.
Include a transition to the first article.
Max 100 words.

7. Product Description

Write a product description for [product name].
Features: [list features]
Target buyer: [persona]

9 Tips to Write a Claude Prompt That Actually Works

If you want to know how to create a prompt that actually delivers — one that gets you a usable draft on the first pass instead of a vague answer you'll rewrite — start here. These 9 rules are the shortest path to the best prompt for Claude, distilled from Anthropic's own prompt engineering guide and battle-tested across thousands of real conversations.

Writing prompts is engineering, not magic. The difference between a vague "help me with this" and a sharp, testable instruction is the difference between a draft you'll throw away and one you can ship. These nine rules are the shortest path to the second kind.

The 9 Rules

1. Name the Output, Not the Task

Replace weak verbs like "review", "help", "look at", "improve" with a specific deliverable: a table, a JSON object, a five-bullet list, a doc, a 200-word summary, three Slack-ready messages.

Why: Vague verbs produce vague drafts. The model has to guess what "good" looks like. If you can't name the output, the model can't either.

Bad: "Help me with this landing page."

Good: "Audit the landing page above. Return a markdown table with three columns: Element, Issue, Fix. Cover hero, CTA, social proof, and footer. No preamble, no recap."

2. Define the Length Up Front

State the count, the word budget, or the structural shape before the model starts writing. "5 bullets" beats "a few bullets." "180 words" beats "a paragraph." "Three sections, first section is the hook" beats "an intro."

For lists, name the first word of each line so the model can parallelize. For prose, add: "No preamble. No recap. No filler."

Why: Without length, models default to verbosity. With length, they constrain themselves. "Five paragraphs" is a different prompt from "write this."

3. Flip Every "Don't" Into a "Do"

Find every don't, avoid, never, without in your prompt. Rewrite each as a positive instruction. Models follow what they should do far more reliably than what they shouldn't.

Bad: "Don't use jargon, don't be vague, don't be preachy."

Good: "Use plain language. Be specific with numbers. State the benefit in one line, then back it with evidence."

Why: Claude 4.7 reads instructions literally. A "don't" tells the model what to filter out; a "do" tells it what to generate. Always bias toward generation.

4. Lead With Action

Strip the throat-clearing. "Can you help me with..." "I'd like you to..." "I need..." — all of these waste the first ~30 tokens of context.

Start with a verb: Write, Draft, Audit, Convert, Generate, List, Summarize, Rewrite, Translate, Score.

Bad: "I was wondering if you could maybe help me think about how to structure a Q3 OKR doc?"

Good: "Draft a Q3 OKR doc. Three objectives, each with 3 key results. Use the SMART format. Audience: CEO + leadership team. 400 words."

Why: The model's first tokens are the most expensive (cache + attention). Spend them on the work, not on politeness.

5. Force Maximum Reasoning

For non-trivial tasks, select the strongest reasoning model and explicitly ask for it. In Claude 4.7, that means Opus with Adaptive Thinking turned on.

Add: "Think before answering. State the assumptions. Walk through the reasoning. Then give the final answer."

For simple, well-defined tasks, do the opposite — turn reasoning off, because you want speed, not analysis paralysis. Claude 4.7's reasoning toggle is your friend.

Why: Reasoning effort is a parameter, not a vibe. You can over-reason a one-line answer and under-reason a strategic decision. Match the tool to the task.

6. Add "Go Beyond the Basics"

For creative and strategic work, ban the lazy defaults. Tell the model: "Don't give me the obvious answer. Pretend I'm a real client who has seen the generic version already. Go one layer deeper."

This single line changes output quality more than any other trick. Pair it with: "List 3 contrarian takes. Then pick the strongest and defend it."

Why: LLMs are trained to be helpful, which defaults to safe, which defaults to generic. The "go beyond" instruction breaks the gradient and unlocks the tail of the distribution.

7. Upload Your Voice

Paste 2-3 sentences of exactly how you (or your brand) sounds. Then add: "Match the style of these examples. Don't tighten it. Don't formalize it. Keep the same rhythm."

Save this as a reusable "about-me" file in PromptLab — paste it once, reference it forever. Voice is the hardest thing for models to nail from instructions alone. Examples are 10x cheaper than adjectives.

Why: "Professional but warm" is meaningless. "Short sentences. Em-dashes. No exclamation marks. Starts with the punchline" is a prompt.

8. Control Tools On Purpose

Decide upfront whether you want the model to use tools — and which ones.

  • Research tasks: "Search the web aggressively. Cite at least 2 sources per non-trivial claim. Quote exact numbers."
  • Speed tasks: "Answer from training. No search. No tools. Go."
  • Workflow tasks: Name the connectors explicitly: "Use Gmail to find the last 3 threads with Acme Corp. Use Calendar to check availability next week. Draft a reply in Slack-ready format."

Why: Claude 4.7 (and GPT-5) call fewer tools by default than 3.5 did. If you want web search or a connector fired, you have to ask. If you don't, say so — otherwise the model burns time and tokens deciding.

9. State the Goal Before the Task

Open the prompt with the win condition, not the workflow.

Bad: "Write me a follow-up email."

Good: "Goal: Get a meeting booked with the Head of Growth at Acme Corp by Friday. Audience: VP of Marketing, 15 years experience, skeptical of cold outreach. Output: 3 follow-up email variations under 80 words each. Subject line under 45 chars."

Name the audience (CRO, not engineer), the deadline, the measurable outcome. A prompt without a goal is a wish. A prompt with a goal is a brief.

Why: The model can trade off tone, length, and depth intelligently — but only if it knows what success looks like. Without a goal, it optimizes for the average of the training data. With a goal, it optimizes for your outcome.

How to Create a Prompt for ChatGPT That Gets 10x Better Results

Most people type two sentences into ChatGPT, get a mediocre answer, and assume the model is "just not that smart." The model is not the bottleneck. The prompt is. The difference between a flat paragraph and a sharp, usable response is almost always structural — and once you learn the structure, the same free model that gave you a C-minus draft will hand you an A.

This guide is the practical, no-fluff version of everything OpenAI's own prompt engineering documentation teaches — condensed into one framework, 12 copy-paste prompts, and the six mistakes that quietly kill ChatGPT output quality. If you've ever wondered how to create a prompt for ChatGPT that actually delivers, this is for you.

Why Most ChatGPT Prompts Underperform

ChatGPT is a generalist. It was trained to be helpful, harmless, and broadly useful across billions of conversation patterns. That training pushes the model toward the statistical middle of any response: safe, balanced, vaguely confident, and rarely surprising.

A good prompt breaks that gradient. It tells the model three things at once: who it is (role), what situation it's writing for (context), and exactly what shape the answer should take (format and constraints). Skip any of those three and you get the average answer. Hit all three and you get the answer you would have written yourself on a good day — in 4 seconds.

The CRISPE Framework: The 6-Part Prompt Recipe

The most consistent framework we've tested across thousands of ChatGPT prompts is CRISPE — an acronym for Capacity, Request, Insight, Statement, Personality, Experiment. It works because it forces you to specify everything the model needs before it starts predicting tokens.

1. Capacity & Role

Tell ChatGPT who it is. A role sets the expertise level, vocabulary, and default frame for the response. Without one, the model defaults to "a helpful assistant," which is the lowest-energy version of itself.

You are a senior conversion copywriter who specializes in B2B SaaS landing pages. You write in the style of Harry Dry (MarketingExamples) — punchy, specific, no fluff.

2. Request (the actual task)

The verb-forward, unambiguous ask. Lead with the action. Skip the "could you please" — it costs tokens and adds nothing.

Write 5 hero-section headlines for a prompt-engineering tool called PromptLab. Each headline must be under 8 words, focus on the pain (writing bad prompts = bad AI output), and avoid the words "revolutionary," "powerful," and "ultimate."

3. Insight (background context)

Everything the model needs to know that isn't in the request itself: audience, product, stage, what was tried before, what's at stake.

Context: PromptLab is a free AI prompt workspace. Target audience is marketers and content creators who already use ChatGPT daily but get inconsistent results. Main differentiator: a Readiness Score that scores any prompt on structure. Competitor copy from Notion AI and Copy.ai is too generic — we want sharper, more opinionated.

4. Statement (the mission / success criteria)

What does "winning" look like? This is the line most prompts skip — and it's the single highest-leverage sentence you can add.

Goal: a headline that, when read alone, makes a marketer stop scrolling and click. Optimized for clarity and curiosity, not cleverness.

5. Personality (tone, voice, style)

Name the voice with examples, not adjectives. "Professional but warm" is meaningless. "Short sentences. Em-dashes. No exclamation marks. Starts with the punchline" is a prompt.

Voice: short sentences. Em-dashes allowed. No exclamation marks. Starts with the verb or the pain, never the brand. Think: Alex Hormozi meets Paul Graham.

6. Experiment (format + iteration instructions)

How should the answer be shaped? Markdown table? JSON? Numbered list? 200 words? And what should the model do if it doesn't know — should it guess, ask, or refuse?

Format: return as a numbered list. Each item is the headline on its own line, no commentary. If you would need more than 8 words, stop and ask before submitting.
💡 The 80/20: Of those six parts, Role + Request + Format do 80% of the work. If you only have time for three lines, write those three. The rest is polish.

1. The "Think Step-by-Step" Reasoning Prompt

For analysis, planning, and decisions. Adding a "let's think step by step" instruction measurably improves accuracy on multi-step problems — this is one of the most replicated findings in prompt engineering research, originally published in the chain-of-thought paper from Google and Princeton.

2. The Few-Shot Style Prompt

The 6 Mistakes That Quietly Kill ChatGPT Output

Even with CRISPE, these six patterns will sabotage your results. They show up in 80% of weak prompts we review.

Mistake 1: Asking the model to do three things at once

"Summarize this article, give me 5 tweet ideas, and write a LinkedIn post." ChatGPT will do all three, but each will be shallower than if you'd asked for one. Fix: either split into 3 prompts, or explicitly tell the model to handle them sequentially with a clear separator.

Mistake 2: No success criteria

"Write me a good email." Good by whose standard? For what outcome? Fix: always close with a one-sentence win condition. "An email that gets a meeting booked by Friday" beats "a good email" every time.

Mistake 3: Trusting the first response

The first answer is the average answer. The third or fourth answer — after a few targeted refinements — is usually 2-3x better. Fix: treat the first response as a draft, not a final.

Mistake 4: Hedging your way into mediocrity

"Maybe you could try to think about whether…" loses ~30% of the model's effort to the hedging. Fix: lead with verbs. "Write. List. Compare. Rank. Decide."

Mistake 5: Forgetting to specify the output format

Without format instructions, the model returns a wall of prose. Fix: always say how the answer should be shaped — bullet list, table, JSON, 200 words, 3 sections. The model is dramatically better at fitting a shape than inventing one.

Mistake 6: Ignoring the model's training cutoff

For anything time-sensitive (news, prices, recent events), ChatGPT will hallucinate. Fix: paste the source material into the prompt, or explicitly say: "If you don't know, say 'I don't know' — do not guess."

Advanced: Chain-of-Thought and Few-Shot — When to Use Them

Two techniques from OpenAI's own prompt engineering guide show up over and over. Here's when each one earns its place.

Chain-of-thought (CoT) — adding "think step by step" or "walk me through your reasoning" before the final answer. It measurably improves accuracy on math, logic, multi-step analysis, and planning. Use it for: decisions, calculations, complex instructions, debugging. Skip it for: simple lookups, formatting tasks, anything that doesn't involve reasoning.

Few-shot prompting — including 2-3 examples of the exact output you want inside the prompt. Use it for: matching a specific style, format, or tone; teaching the model a pattern; getting consistent outputs across many similar requests. Skip it for: one-off questions where the format is obvious.

The two stack. Few-shot examples that include reasoning ("here's an example of a thought-out answer") outperform plain few-shot on hard problems — this is the variant from the original chain-of-thought paper by Wei et al.

Putting It All Together

You don't need to memorize CRISPE. You need to remember three questions before you hit enter:

  1. Who should the model be? (Role)
  2. What shape should the answer take? (Format)
  3. What does "winning" look like? (Success criterion)

Best Prompt for Marketing: 7 Templates That Convert in 2026

Most marketing prompts produce copy that sounds like copy. The cadence is right, the format is right, and the conversion is still zero. The model isn't the problem — the prompt is. The difference between an AI paragraph that gets scrolled past and one that actually moves a metric comes down to a small set of structural decisions you make in the first 50 words of the prompt.

This guide is the practical, no-fluff version of what actually works in 2026 for marketers using AI. It contains 7 copy-paste templates — for social media, email, ads, landing pages, and product copy — each one tested against ChatGPT, Claude, and Gemini, and each one built on the same 6-part structure that our general prompt engineering guide recommends. If you've ever wondered how to create the best prompt for marketing that actually converts, this is for you.

Why Most Marketing Prompts Underperform

Marketing is a high-volume discipline. Most teams ship more copy in a week than a novelist ships in a year. That volume creates a temptation: keep the prompts short so you can move fast. The result is predictable — generic ad copy, on-brand-sounding captions that don't differentiate, and email subject lines that could be from any company in any industry.

The OpenAI prompt engineering guide, Anthropic's prompt engineering for business performance playbook, and the Microsoft prompt engineering documentation all converge on the same diagnosis: a marketing prompt needs more structure, not less. The most cited common failure is leaving the model to guess three things it can't possibly know: who the audience is, what conversion looks like, and what the offer is. When those three are missing, the model defaults to the statistical middle of its training data — which is the same place every other brand's copy is coming from.

A good marketing prompt is the opposite of generic. It names the funnel stage, the offer, the objection being addressed, and the conversion event. It tells the model to write as a specific persona, not as "a marketer." And it specifies the format, the length, and the call-to-action down to the verb.

The CRISPE-Marketing Framework: A 6-Part Prompt Recipe

The framework below is a marketing-tuned version of CRISPE — the 6-part prompt structure we cover in our Claude prompting guide and our general prompt engineering series. It is the same skeleton used by teams at companies like Anthropic and HubSpot to build production-grade marketing prompts.

1. Capacity & Role

Tell the model who it is. A role sets the expertise level, vocabulary, and the default frame for the response. For marketing, the role you pick changes the output dramatically — a "senior B2B SaaS copywriter" and a "DTC copywriter" produce completely different email subject lines from the same brief.

You are a senior conversion copywriter who specializes in B2B SaaS. Your writing style is sharp, specific, and benefit-driven — think Alex Hormozi meets Harry Dry (MarketingExamples). You never use the words "revolutionary," "powerful," or "ultimate."

2. Request (the actual marketing task)

The verb-forward, unambiguous ask. Lead with the action. Skip the "could you please" — it costs tokens and adds nothing to the response.

Write 5 LinkedIn ad headlines for a prompt-engineering tool called PromptLab. Each headline must be under 70 characters, lead with the pain (writing bad prompts = bad AI output), and end with a curiosity hook. Avoid superlatives.

3. Insight (background, audience, offer)

Everything the model needs to know that isn't in the request itself: funnel stage, audience, offer, price point, competitor copy, and what was tried before.

Context: PromptLab is a free AI prompt workspace. Target audience: marketing managers at B2B SaaS companies with 10-200 employees who already use ChatGPT daily but get inconsistent results. Offer: free, no credit card. Main differentiator: a Readiness Score that scores any prompt on structure. Competitor copy from Notion AI is too generic — we want sharper, more opinionated. Funnel stage: top-of-funnel awareness, optimizing for click-through to a free signup page.

4. Statement (the success criteria)

What does "winning" look like? For marketing, this is almost always a measurable outcome — click-through, reply rate, conversion, signups. State it explicitly.

Goal: a headline that, when read alone in a LinkedIn feed, makes a marketing manager stop scrolling and click. Optimized for clarity and curiosity, not cleverness. Benchmark to beat: 1.8% CTR (current LinkedIn ad average for B2B SaaS).

5. Personality (tone, voice, style)

Name the voice with examples, not adjectives. "Professional but warm" is meaningless. "Short sentences. Em-dashes. No exclamation marks. Starts with the punchline" is a prompt.

Voice: short sentences (max 12 words). Em-dashes allowed. No exclamation marks. Starts with the verb or the pain, never the brand. Banned words: revolutionary, powerful, ultimate, unleash, supercharge, robust. Reference voice: the Punch magazine copy in Alex Hormozi's $100M Offers.

6. Experiment (format + iteration)

How should the answer be shaped? Markdown table? JSON? Numbered list? 200 words? And what should the model do if it doesn't know — should it guess, ask, or refuse?

Format: return as a numbered list. Each item is the headline on its own line, no commentary, no preamble. If you would need more than 70 characters, stop and shorten before submitting. If you would use a banned word, pick a different one.
💡 The 80/20: Of the six parts, Role + Request + Format do 80% of the work. If you only have 60 seconds to write a marketing prompt, write those three. The rest is polish that becomes more important as the stakes of the campaign go up.

3 Marketing Prompt Mistakes That Kill Conversion

Even with the templates above, three patterns consistently undermine marketing output. Spotting them in your own prompts is the difference between copy that ships and copy that gets stuck in revision.

Mistake 1: Writing for "Everyone"

"Write copy for small business owners" produces copy that resonates with no one. Marketing copy is most effective when it speaks to one specific person, in a specific role, with a specific objection. The prompt above replaces "audience" with as much demographic and psychographic detail as you can fit in 2-3 sentences. If you can't fill in the bracketed parts of the templates, you don't know your audience well enough to write copy for them — and the model can't fill the gap.

Mistake 2: Skipping the Funnel Stage

Cold traffic and warm retargeting need different copy. Cold traffic needs an interruption — a hook, a question, a counterintuitive claim. Warm retargeting needs reinforcement — a feature, a comparison, a number that proves the claim. A prompt that doesn't specify the funnel stage produces average output for both. The templates above name the stage explicitly in the Context block. Don't skip it.

Mistake 3: Trusting the First Output

Marketing copy is the highest-volume use case for LLMs, and the first output is rarely the best. Treat the first response as a draft, then iterate with one targeted refinement. The most common high-leverage refinement is: "Rewrite the 3 strongest variations, but with a specific stat or proof point from this list: [paste proof points]." Adding a real number to a generic claim is the single fastest way to lift CTR on a marketing prompt.

Claude vs GPT-5 vs Gemini: Best Prompting Practices for Each

Take the same prompt — “Write a 200-word LinkedIn ad for an AI prompt tool, pain-first, no superlatives” — and run it on Claude 4.7, GPT-5, and Gemini 2.5. You will get three different outputs. One will lead with the pain, one will lead with the brand, and one will produce a paragraph that reads like a press release. The model you pick changes the result more than the words you write.

This guide is the model-specific playbook for the three models that matter in 2026. It is built on the official prompting guidance from Anthropic, OpenAI, and Google — and tested against the same 5 production prompts in our Claude guide and our ChatGPT vs Claude comparison. By the end, you will know exactly which prompt pattern fits each model, and which one to reach for when you need a particular output shape.

Why One Prompt, Three Different Models, Three Different Answers

Every modern LLM is trained on the same internet, but they are not the same model. They differ in three ways that matter for prompting: pre-training objective (what they were optimized to be good at), post-training alignment (how RLHF tuned their voice and refusal behavior), and inference infrastructure (what reasoning modes the API exposes). The result is that the same prompt lands on three different “personalities.”

OpenAI’s official GPT-5 Prompting Guide says it directly: GPT-5 is “very adaptive and requires very specific instructions,” and was trained to be a strong foundation for agentic and tool-calling flows. Anthropic’s Claude Prompting Best Practices emphasizes XML-style structure, long-context handling, and adaptive thinking. Google’s Prompt Design Strategies for Gemini focuses on natural-language flexibility, multimodal inputs, and thinking models like Gemini 2.5 Pro.

The gap is not intelligence. All three are at the frontier. The gap is in shape: which instructions each model translates most reliably into the output you want. The rest of this guide is the shape-by-shape map.

Quick Comparison: Claude 4.7 vs GPT-5 vs Gemini 2.5 Pro

Before the deep dive, here is the 90-second view. Use this as a decision tree when you are picking a model for a specific task.

  • Best for long, structured reasoning: Claude 4.7 Sonnet/Opus. XML tags, multi-step plans, and careful instruction-following.
  • Best for agentic + tool calling: GPT-5. The Responses API persists reasoning across tool calls, and the model is tuned to plan-and-execute.
  • Best for multimodal + real-time grounding: Gemini 2.5 Pro. Native image, video, and audio understanding, plus Google Search grounding in the API.
  • Best for short, creative copy: GPT-5 — but only with explicit length and format constraints.
  • Best for code review and careful refactors: Claude 4.7 Sonnet — more literal, less overeager, fewer false positives.
  • Best for research synthesis across many sources: Gemini 2.5 Pro with thinking enabled — 1M+ token context, ground with Search.
💡 Practical rule: Pick the model by output shape, not by leaderboard score. If you need a JSON object, the model that follows JSON schemas most literally wins. If you need an essay, the model with the most coherent long-form planning wins. If you need a multimodal analysis, the only model that sees all the modalities is the one to pick.

How to Write the Best Prompt for Claude 4.7

Claude is the model to reach for when the prompt has many moving parts. It is the most literal instruction-follower at the frontier, which is a feature when you have a complex brief and a bug when your brief is sloppy. Anthropic’s official guidance puts it this way: “Be clear and direct. Add context to improve performance. Use examples effectively.”

1. Use XML Tags to Separate Sections

Anthropic explicitly recommends XML-style tags for structured prompts. The model is trained to respect XML boundaries, so instructions inside <instructions> are interpreted as instructions, not as data or context. The same prompt without tags will produce an output that “blurs” the sections — the model starts to follow an example as if it were an instruction.

<role>
You are a senior B2B SaaS copywriter with 10 years of experience.
You write in the style of Alex Hormozi and Harry Dry.
</role>

<context>
Product: PromptLab, a free AI prompt workspace.
Audience: marketing managers at B2B SaaS companies, 10-200 employees.
Funnel stage: top-of-funnel awareness. Offer: free, no credit card.
</context>

<task>
Write 5 LinkedIn ad headlines. Each one:
- Under 70 characters
- Leads with the pain, not the brand
- Ends with a curiosity hook
- Banned words: revolutionary, powerful, ultimate, unleash
</task>

<output_format>
Return as a numbered list. One headline per line. No commentary.
</output_format>

2. Turn On Adaptive Thinking for Hard Tasks

Claude 4.7 ships with adaptive thinking — instead of a fixed reasoning budget, the model decides how much to think based on the prompt. For analytical, multi-step, or strategic work, set the effort parameter high and let the model reason out loud before it answers. For simple lookups and short copy, set effort low or off — you want speed, not analysis paralysis.

Anthropic’s docs call out a specific 4.6+ migration: adaptive thinking replaces the older budget_tokens parameter. If you are upgrading an existing app, swap the budget for thinking: {type: "adaptive"} and tune the effort field.

3. Use Prefill and Stop Sequences to Lock the Output Shape

Claude supports prefill — you can write the first few tokens of the assistant’s response before the model takes over. The Anthropic prompt engineering guide recommends prefill as a way to force JSON, skip pleasantries, and bias the model toward a specific output structure. (As of Claude 4.6+, the API is moving away from prefill for some workflows in favor of explicit response preambles — check the migration notes if you have an older app.)

Assistant: {

When the assistant’s response must start with a JSON brace, the model will fill in the object instead of writing “Sure! Here is a JSON object:”. That single change often doubles the parsing reliability of downstream code.

4. Long Context: Put the Document First, Then the Question

Claude’s 200K+ token context window means you can paste entire books, codebases, or transcripts. The Anthropic guidance: put the long document first, then the instructions, then the question. This mirrors how the model is trained on long-context retrieval and reliably improves answer accuracy on “needle in a haystack” questions by 5-15%.

How to Write the Best Prompt for GPT-5

GPT-5 is the most “adaptive” model at the frontier. OpenAI’s official guide makes the point explicit: minimal prompts work best for Codex-style tasks, but for general-purpose prompts you should be precise and avoid conflicting information. The single biggest mistake people make with GPT-5 is treating it like GPT-4 — over-engineering system prompts and adding rules that conflict with each other.

1. Set the Right Reasoning Effort

GPT-5 introduces a reasoning_effort parameter with four settings: minimal, low, medium, and high. The default is medium. The OpenAI guide is explicit: for coding and agentic tasks, you usually want medium or high. For one-line answers, classification, or extraction, set minimal and the model will answer in a single forward pass with no chain-of-thought overhead.

The mistake: leaving reasoning_effort at the default medium for a quick lookup. The model will burn 3-10x more tokens than needed to reason about a question that does not need reasoning. Set it explicitly. The cost savings are real.

2. Use the Responses API for Agentic Work

OpenAI’s guide recommends the Responses API over the older Chat Completions API for any agentic or tool-calling flow. The reason: reasoning state is persisted between tool calls. The model can think about the result of one tool call, decide what to call next, and only emit a final answer when it is ready. With Chat Completions, you have to rebuild the reasoning state on every call — slower, more expensive, and prone to loops.

3. Tell GPT-5 to Proceed Under Uncertainty

One of the highest-leverage prompt patterns from the GPT-5 guide: tell the model to proceed when it is uncertain instead of stopping and asking. The example from the docs: “Never stop or hand back to the user when you encounter uncertainty. Decide what the most reasonable assumption is, proceed with it, and document it for the user’s reference after you finish acting.”

This is the opposite of the Claude default, which is more conservative and more likely to ask. For agentic workflows that need to ship, GPT-5’s bias toward action is a feature — but only if you tell the model to document its assumptions as it goes, so you can audit them.

4. Be Specific About Tool Use

GPT-5 calls fewer tools by default than 3.5. If you want the model to use web search, file search, or a custom connector, you have to say so explicitly. The OpenAI guide recommends phrasing tools as optional but encouraged rather than mandatory: “Use web search when the answer depends on information that may have changed since the training cutoff. Cite at least one source per non-trivial claim.”

You are a research analyst. For the question below, use web search when the answer depends on recent data. Cite sources inline with [1], [2] notation. If you use a tool, summarize what you searched for and what you found before giving the final answer.

Question: [YOUR QUESTION HERE]

How to Write the Best Prompt for Gemini 2.5 Pro

Gemini is the most flexible of the three — it accepts natural-language prompts in almost any shape and is trained to be the most conversational. The Google Prompt Design Strategies documentation emphasizes that Gemini is designed to be talked to like a person, and the model’s biggest strength is multimodal: it can read images, video frames, and audio alongside text in a single prompt.

1. Lean Into Multimodal Inputs

If your task involves a screenshot, a photo, a chart, or a video, Gemini is the model to reach for first. The Google blog introducing Gemini 2.5 Pro emphasizes the model’s “enhanced performance and improved accuracy” on multimodal reasoning, and the API accepts images, video frames, and audio natively without any preprocessing.

For text-only tasks, Gemini is still strong — but the differentiator is the multimodal angle. The most underrated use case is uploading a screenshot of a UI bug and asking for a fix: Gemini reads the layout, identifies the CSS class, and proposes a patch in a single shot.

2. Use Thinking Mode for Multi-Step Reasoning

Gemini 2.5 Pro is a thinking model — it reasons before it answers. The Google docs recommend explicitly turning thinking on for math, code, and research tasks. The model will show its work (configurable), and the answer quality is materially better on multi-step problems than the non-thinking Gemini 2.0 Flash baseline.

The pattern: combine thinking with structured output. Tell the model to reason step-by-step, then emit a final JSON object. Gemini handles the format better than Claude or GPT-5 when the format is JSON Schema — the model’s training data includes more schema-typed examples.

3. Ground with Google Search

For any task that depends on current information — pricing, recent news, stock prices, latest product features — use Gemini with the Search tool enabled. The Google AI Studio lets you toggle Search grounding with one click, and the API exposes it as tools: [{google_search: {}}]. The model will cite sources inline and link to the pages it used.

This is Gemini’s killer feature for research workflows. The combination of 1M+ token context, multimodal input, and real-time Search grounding means a single Gemini call can replace a multi-step research pipeline that would otherwise take 5-10 Claude or GPT-5 calls.

4. Describe the Scene, Don’t List Keywords

For image generation with Gemini 2.5 Flash Image, the Google Developers Blog is explicit: “Describe the scene, don’t just list keywords.” The model’s core strength is language understanding, so a paragraph describing the composition, lighting, and mood produces a much better image than a comma-separated list of style tags. This is the opposite of how Midjourney is tuned — see our image generation guide for the side-by-side comparison.

3 Model-Specific Mistakes to Avoid

Even with a great template, three patterns consistently produce bad output on the wrong model. Spot them before you ship.

Mistake 1: Asking Claude to Reason Without Giving It a Structure

Claude 4.7 with adaptive thinking will reason — but it reasons best when given a structure to reason within. Mistake 2: Asking GPT-5 to Do Quick Lookups With Reasoning Turned On

The OpenAI guide is explicit: “For one-line answers, set reasoning_effort = minimal.” A lookup question with medium reasoning is 3-10x more expensive and 2-5x slower than the same call with minimal. Gemini 2.5 Pro has a knowledge cutoff. If you ask it for the current price of a stock, the latest version of a software product, or a recent news event, the model will answer from training data — which may be months or years out of date. The fix is one line in the prompt: “Use web search to find the current value. Cite the source.” Without that line, you will get confident answers that are subtly wrong.

How to Write a Prompt for Image Generation (Midjourney, DALL-E, Flux)

Type "a cat" into Midjourney, DALL-E, and Flux and you get three different cats in three different styles on three different backgrounds. Type a 6-part structured prompt and you get a portfolio-grade render that looks the way you actually imagined it. The gap between those two outputs is not the model — it is the prompt. This guide is the 6-part image prompt formula that closes that gap, with model-specific tuning for the three generators that matter in 2026.

Everything below is built on the official documentation from our general prompt engineering guide, Midjourney's Prompt Basics, the FLUX.2 Prompting Guide from Black Forest Labs, and OpenAI's DALL-E guidance. If you have ever pasted a one-line idea and gotten a one-line image back, the rest of this article is the fix. For a side-by-side comparison of how the same prompt lands on ChatGPT vs Claude vs Gemini, see our Claude vs GPT-5 vs Gemini breakdown — image generation is a separate but related skill, and the same model-specific thinking applies.

Why "A Cat" Is Not a Prompt

Image generators are not search engines. They do not retrieve "a cat" — they synthesize a cat from noise, conditioned on every word in your prompt. A vague prompt hands the model 95% of the creative decisions. A structured prompt hands the model exactly the 4-6 decisions that matter and lets it spend the rest of its capacity on rendering quality. The result of the second kind of prompt is sharper, more on-brief, and closer to what you actually pictured.

Midjourney's own docs make the point sharper: "Short and simple prompts typically generate the best images with Midjourney." The trick is that "short" does not mean "vague." It means "every word does work." The FLUX.2 Prompting Guide agrees: priority order is main subject → key action → critical style → essential context → secondary details. Every word in a good image prompt is on that priority list.

Black Forest Labs puts a hard cap on it: the FLUX.2 prompt length guidance is 2-3 sentences, with the most important elements first. OpenAI's DALL-E guidance, by contrast, tolerates (and rewards) longer natural-language descriptions. The three models want the same information, but they want it in three different shapes. That is the whole game.

The 6-Part Image Prompt Formula

Before we go model-by-model, here is the universal formula. It works on Midjourney, DALL-E, and Flux (with the model-specific tweaks in the next sections). Use it as a checklist whenever you sit down to write a prompt — most of the time, the difference between a weak output and a strong one is whether you filled in all 6 parts.

  1. Subject — the main object, person, animal, or scene. Be specific: "a calico cat" beats "a cat". "three children in raincoats" beats "kids."
  2. Action / Pose — what the subject is doing. "mid-leap," "looking over its shoulder," "hands in pockets." If you skip this, the model guesses and the guess is usually "standing still and looking at the camera."
  3. Environment / Setting — where the subject is. "on a wet cobblestone street at dusk," "in a glass terrarium," "floating in zero gravity."
  4. Lighting — how the scene is lit. "soft window light from camera left," "harsh neon underlight," "golden hour backlight." Lighting is the single biggest factor in mood and the easiest one to skip.
  5. Style / Medium — the artistic rendering. "shot on 35mm film," "watercolor illustration," "3D isometric render in Blender," "Studio Ghibli animation cel."
  6. Composition / Framing — where the camera is. "wide shot, low angle, rule of thirds," "extreme close-up of hands," "top-down flat lay."
💡 The 6-part rule: If you can fill in all 6 parts, you have a professional image prompt. If you can only fill in 2-3, the model will fill in the rest — and it will guess generic. Specify what you can, leave the rest to the model, and be honest about which parts matter most for the shot.

Here is the same 6-part formula applied to a real prompt. Read it left-to-right and notice how every part has a job:

A calico cat (Subject)
mid-leap off a wooden fence (Action)
in a sunlit cottage garden full of lavender (Setting)
lit by warm golden-hour backlight (Lighting)
shot on 35mm film with shallow depth of field (Style + Composition)
--ar 3:2 --v 7 (Midjourney parameters)

That single prompt would land well on all three models. The next three sections show you how to tune it for each one specifically.

How to Write the Best Midjourney Prompt

Midjourney is tuned for short, evocative, comma-separated prompts with a clear subject, medium, and mood. The official Prompt Basics doc is explicit: "Short and simple prompts typically generate the best images." But "short" means every word pulls weight, not that the prompt is underspecified. The trick is to think in modifiers, not sentences.

1. Lead with the Subject and Action

Midjourney weighs the first few words the most. Put the subject and what it is doing at the front, then layer on style and environment. The model treats modifiers as ranking cues — earlier words dominate the output, later words adjust.

A weathered sailor in a yellow slicker, steering a fishing boat through a storm, cinematic photograph, dramatic lighting, ocean spray, shot on 35mm film, --ar 16:9 --v 7 --style raw

The --style raw parameter reduces Midjourney's default beautification and gets you closer to the prompt you actually wrote. Use it for product shots, technical illustrations, and any time the default looks "too polished."

2. Use the --no Parameter Instead of "No" Words

The Midjourney docs are clear: "Describe what you do want instead of what you don't. If you mention a party with 'no cake,' a cake might still appear." Negations are unreliable in diffusion models. Use the --no parameter to exclude elements you do not want in the output.

Editorial portrait of a female CEO in a minimalist office, soft window light, 85mm lens, neutral expression, no smile --no smile teeth makeup

The --no parameter is a hard exclusion — Midjourney actively steers the image away from those tokens. The list should be short (3-5 terms) and specific. Do not try to exclude abstract concepts like "boring" or "generic." Stick to concrete visual elements.

3. Stack Style References with --sref for Visual Consistency

Midjourney's --sref (style reference) parameter lets you anchor a generation to the visual language of another image. For brand work, character sheets, and product families, this is the most underrated tool in the suite. Pick a single reference image whose style you want to imitate, upload it, and pass its URL with --sref URL.

A minimalist product hero shot of a ceramic coffee mug on a marble surface, soft natural light, lifestyle photography --sref https://example.com/your-brand-style.jpg --ar 4:5 --v 7

For a series, use the same --sref URL across 20-30 prompts and the output will hold a consistent visual language — same color grade, same lighting feel, same level of polish. This is the closest thing Midjourney offers to a "brand kit," and it is the highest-leverage tool for any work that ships in volumes.

4. Use Multi-Prompts and Weights for Fine Control

Midjourney's :: syntax lets you weight parts of a prompt. A part with ::2 is twice as influential as a part with no weight. This is the right tool when one element needs to dominate the output and another needs to be a background detail.

red fox in a snowy forest::2 autumn leaves on the ground::1 soft bokeh background::0.5 --ar 3:2

The first part (red fox) is the dominant subject, the second (autumn leaves) is mid-priority, the third (bokeh) is a subtle background modifier. Read the weights as a hierarchy, not as a recipe.

How to Write the Best DALL-E Prompt

DALL-E is the most "conversational" of the three image generators. It accepts natural-language paragraphs and tends to follow longer, more descriptive prompts better than Midjourney or Flux. OpenAI's guidance: be specific about the scene, the lighting, the camera, the mood, and the style, and let the model interpret the prose.

1. Write a Scene Description, Not a Tag List

The DALL-E 3 prompting community has converged on a clear pattern: paragraphs beat tag lists. A scene description reads like a film director's shot list — subject, action, environment, lighting, camera. The model interprets the prose, infers the relationships, and produces a coherent image.

A cinematic wide shot of a lone astronaut standing on the edge of a red Martian canyon at sunset. The astronaut's visor reflects the canyon walls. The sky is dusty pink and amber. Low camera angle, looking up at the astronaut. Photorealistic, shot on ARRI Alexa, anamorphic lens flare.

Notice the structure: opening framing (cinematic wide shot), subject (astronaut), setting (Martian canyon at sunset), specific detail (visor reflection), color (dusty pink, amber), composition (low angle, looking up), rendering (photorealistic, ARRI Alexa). DALL-E 3 handles this kind of paragraph better than a comma-separated tag list.

2. Specify Style and Reference Artists Carefully

DALL-E will produce images in the style of named artists, art movements, and even specific films — but the results depend heavily on the model's training data. Photography styles (35mm, polaroid, shot on iPhone, National Geographic) work very reliably. Art movements (Bauhaus, art deco, impressionism) work well. Named living artists are often rejected or produce inconsistent results. If you want a 1940s noir look, say so explicitly: "1940s film noir, high-contrast black and white, venetian blind shadows, femme fatale silhouette." That works. "Like that movie" does not.

3. Avoid "Don't" — Use "Do" Instead

Like Midjourney, DALL-E handles negations unreliably. Saying "no text" or "no watermark" often produces text and watermarks. The fix is to say what you want instead of what you do not want, and to make the positive instruction as concrete as possible.

A clean product photograph of a white ceramic vase on a seamless light gray background, soft even studio lighting, no visible text, no logos, no props, no reflections

Notice the trick: the prompt says "no text, no logos, no props, no reflections" — but those words are surrounded by positive framing ("clean product photograph," "seamless light gray background") that anchors the model in the do-state. Pure negation produces unpredictable results; positive framing with selective negative qualifiers is much more reliable.

4. For Text in Images, Use Quotation Marks and Specify the Font

One of the most-requested DALL-E features is reliable text rendering. The community guidance: use quotation marks around the literal text, specify a font style, and keep the text short (3-5 words is the sweet spot).

A vintage travel poster for Paris, the text "PARIS" in large bold art-deco serif letters at the top, "BONJOUR" in smaller letters below, soft watercolor background of the Eiffel Tower at sunset

For longer text, DALL-E still struggles. If you need a poster with a paragraph of body copy, the right workflow is to render the image without text, then composite the text in a tool like Figma or Photoshop. Treating DALL-E as the image layer and a design tool as the typography layer is the reliable production workflow.

How to Write the Best Flux Prompt

FLUX (Black Forest Labs) is the newest of the three, and its prompt format reflects that. The official FLUX.2 Prompting Guide is explicit: "No negative prompts. FLUX.2 does not support negative prompts." And: "FLUX.2 generates photorealistic images from simple, natural language prompts." The format is closer to DALL-E (natural language paragraphs) than to Midjourney (tag lists with parameters).

1. Use the Subject + Action + Style + Context Framework

Black Forest Labs' official guidance for FLUX.2 is a clean four-part framework: Subject + Action + Style + Context. Priority order is main subject → key action → critical style → essential context → secondary details. Put the most important elements at the start of the prompt; let the modifiers fall where they may.

A determined young woman (Subject) climbing a sheer rock face (Action), in cinematic wide-angle style with golden hour backlighting (Style), in a misty mountain valley at sunrise (Context)

The four parts are easy to write quickly, and the priority order is the same as the priority order of attention in the model. The result is a prompt that the model can render with high fidelity on the first try.

2. Use Hex Codes for Brand Colors

One of FLUX.2's most underrated features: it understands hex codes. The official docs are explicit: "Use hex codes for brand text: 'The logo text "ACME" in color #FF5733'." For brand work — logos, packaging, marketing assets — this is the cleanest way to lock in a specific color.

A minimalist product render of a stainless steel water bottle on a pure white background, the brand text "HYDRO" in bold sans-serif letters in color #2A9D8F on the side of the bottle, soft studio lighting, no shadows

Compare that to the DALL-E version of the same prompt, which would have to describe the color as "teal green" or "muted blue-green" and would produce variable results. The hex code removes ambiguity.

3. Do Not Use Negative Prompts (Use Positive Framing)

FLUX.2 does not support the --no style negative prompt. To exclude something, describe the output you want in positive terms — and the model will not render the unwanted element if the positive description is strong enough. "A clean product photograph on a pure white background, no visible shadow, no other objects, no people" works because the positive framing ("clean," "pure white," "no shadow") anchors the model. The negations reinforce; they do not lead. Same approach as DALL-E, same reason it works.

4. For Photorealism, Specify Camera and Lens

FLUX.2 is trained heavily on photographic data, and the model's strongest photorealism comes from prompts that name the camera, lens, and lighting setup. The community has converged on a clean pattern: "shot on [camera] with [lens] under [lighting]".

A candid street photograph of an elderly man feeding pigeons in a European city square, shot on a Leica M11 with a 35mm Summicron lens, late afternoon natural light, shallow depth of field, grain

The named camera (Leica M11) and lens (35mm Summicron) trigger specific photographic training data in the model. The result is a more "photographic" image than a generic "candid street photograph" would produce. This is the single highest-leverage technique for FLUX.2 photorealism, and it composes with the next section: same prompt, three different formats, three different results.

Side-by-Side: The Same Prompt, Three Models

Here is a real test. Same idea, three models, three different prompt formats. The differences are immediate and instructive.

The Test Idea

Midjourney Output

3 Image Prompt Mistakes to Avoid

Even with a great template, three patterns consistently produce bad output. Spot them before you burn 50 generations.

Mistake 1: Vague Subjects

"A person" is not a subject — it is a category. The model has to invent the person from scratch, and the result is generic. A real subject has at least three identifying details: who they are, what they are wearing, and one piece of context. "A tired barista in a green apron, holding a steaming espresso." That is a subject. "A woman in a coffee shop." That is not.

Mistake 2: Skipping Lighting

Lighting is the single biggest factor in mood, and it is the easiest one to skip. A prompt that says nothing about lighting gets the model's default — flat, even, "product photography" lighting. If you want a mood (moody, dramatic, hopeful, warm), you have to describe the light. "Soft window light from camera left" is better than "moody." Specific lighting cues produce specific results.

Mistake 3: Trying to Get Text in the First Generation

Text rendering is the worst-supported feature in image generation. Midjourney is best at short words in stylized fonts. DALL-E handles short quotes in quotation marks. Flux is best with brand colors and hex codes. None of them are reliable for body copy. If you need a poster with a paragraph of text, the right workflow is to render the image first, then composite the text in a design tool. Trying to get 15 words right in a single generation is the fastest path to 50 wasted credits.

🚀 Test in 60 seconds: Pick one of the templates above, fill in the six lines for a real product or scene, then run it on Midjourney, DALL-E, and Flux side-by-side. Use the same subject and lighting across all three; the only difference should be the format. The model that produces the closest match to your reference is the one to standardize on — and the format that produced it is the one to save as a reusable template.

Putting It All Together

The 6-part formula — subject, action, environment, lighting, style, composition — is the spine. Model-specific tuning is the muscle. Midjourney wants short, comma-separated modifiers with parameters. DALL-E wants natural-language scene descriptions. Flux wants natural language plus specific camera and lens vocabulary. Pick the model by the use case, pick the format that fits the model, and run the 6-part checklist before you generate. One formula, three models, no magic keywords.

AI Prompt for Email Writing: 5 Templates That Get Replies

Ask ChatGPT or Claude to "write a cold email" and you get a wall of polite, generic, instantly-skippable text. "I hope this email finds you well." "I wanted to reach out regarding." "Let me know if you have any questions." Every one of those lines trains the recipient to delete the message. The reason is not the model — it is the prompt. A vague prompt hands the AI every creative decision, and the AI defaults to the same corporate template it learned from millions of training emails. A structured prompt hands the AI only the decisions that matter — who is this person, what do they care about, what is the specific ask — and the result is an email that sounds like a human wrote it for that one specific reader.

This guide is the structured version. Five copy-paste email prompts for the five emails that eat the most time: cold outreach, follow-ups, internal updates, sales proposals, and customer support. Each template is built on the 5-part prompt structure from our general prompt engineering guide, tested across ChatGPT, Claude, and Gemini, and tuned with the model-specific tweaks from our Claude vs GPT-5 vs Gemini comparison. For the marketing-angled version of these prompts — landing pages, ad copy, social — see 10 Prompt Templates Every Marketer Needs.

Why "Write Me an Email" Is Not a Prompt

Email is one of the highest-context tasks you can throw at an LLM. The model has to infer the relationship between sender and recipient, the prior history, the desired outcome, the right tone, the right length, and the right level of formality — all from a one-line instruction. The default behavior is to assume "business professional, neutral, generic," which is exactly the voice that gets archived. The fix is the same as it is for any other prompt: name the output, define the constraints, give an example, and tell the model what success looks like.

Regie.ai's research on AI prompts for sales emails makes the point: AI prompts enable hyper-personalization at scale because the model can synthesize prospect data, persona, and intent into a single message that reads like a one-to-one email. The output quality is a function of input specificity. The "system prompt" sets the tone, voice, and rules for the whole sequence; the "user prompt" fills in the specific prospect, hook, and ask. Most "this AI email sounds robotic" complaints are actually "this prompt was too vague" complaints in disguise.

There is one more thing to internalize before the templates. Reply rate is not the same as open rate. An email can get a 70% open rate and a 0% reply rate if the ask is unclear, the next step is missing, or the subject promised something the body did not deliver. Every prompt below is built to optimize for reply, not open — which means a clear CTA, a low-friction next step, and a reason to respond that is not "just wanted to follow up."

The 5-Part Email Prompt Framework

Before the templates, here is the universal structure. Every email prompt should fill in all five parts. If you can only fill in three, the model will fill in the rest — and the default is the kind of email that gets archived.

  1. Role & Recipient — who is writing, who is reading, and what is the relationship. "I am a SaaS founder writing to a VP of Sales at a 50-100 person company" is a role. "I am writing a sales email" is not.
  2. Context & Hook — what just happened, or what specific thing about the recipient triggered this email. A trigger event (new funding, a job change, a published post, a recent purchase) is the single biggest lever on reply rate.
  3. Value Proposition — what is in it for the recipient, in one sentence. Not a feature list, not a company bio. A specific outcome: save 4 hours a week, close 20% more deals, cut support response time in half.
  4. Ask / CTA — the specific, low-friction next step. "Open to a 15-minute call next week" beats "let me know if you want to chat." A calendar link beats "find time on my calendar."
  5. Format & Tone Constraints — length (under 80 words for cold email, 40-60 for follow-up), tone (casual, formal, peer-to-peer), signoff, and any specific phrases to avoid.
💡 The personalization rule: Parts 1, 2, and 3 must be specific to this recipient. If you can swap the recipient name and the email still works, it is too generic. The first follow-up email in a cold sequence can lift reply rates by 220% over a single send — and the difference between a follow-up that gets a reply and a follow-up that gets ignored is whether the second email adds new context, not whether it is "just checking in."

That is the framework. The next five sections are the templates — one for each of the five emails that eat the most time.

1. Cold Outreach Prompt

The hardest email to write is the first one. The recipient did not ask for it, does not know you, and has 200 other unread messages. The job of a cold email is not to close a deal — it is to earn a 6-line reply. Here is the prompt:

You are a B2B sales rep at a SaaS company. Write a cold outreach email under 80 words.

ROLE: I am writing to a [job title] at a [company size] company in [industry].
HOOK: They [specific trigger event — e.g., "just announced a Series B led by Accel" / "published a post on reducing support response time" / "hired their first RevOps lead last month"].
VALUE: We help companies like [reference customer] [specific outcome — e.g., "cut sales email drafting time by 70% while lifting reply rates 2x"]. One specific result: [reference customer] went from 4% to 11% reply rate in 6 weeks.
CTA: Open to a 15-minute call next week? I will send a specific agenda, not a generic demo.
TONE: Peer-to-peer, no fluff, no "I hope this finds you well." No exclamation marks.
SIGN-OFF: [Your name], [one-line title]

Example Output

Subject: 11% reply rate in 6 weeks

Hi Sarah,

Saw you just hired your first RevOps lead at Northwind — congrats. Most teams in that window spend 6-8 hours/week drafting outbound that converts at 3-4%.

We helped Replicant (similar profile, 60 reps) go from 4% to 11% reply rate in 6 weeks, while cutting drafting time by 70%. The short version: structured prompts + a sequenced follow-up framework, not magic.

Open to a 15-minute call next week? I will send a specific agenda — what to do in the first 30 days, what to skip.

Best,
Alex Chen
Head of Outbound, Acme

P.S. The Replicant teardown is here if you want the data first: [link]
🚀 The follow-up move: The first follow-up should add new context, not just "bump." Apollo's data on reply rates finds that SDRs should send a maximum of three follow-ups per sequence. Instantly's research agrees: 55% of replies to cold email campaigns come from a follow-up email, not the initial message. The 2-5 day cadence (most sequences use 3-day intervals) is the proven range.

2. Follow-Up Prompt (Bump with Value)

Most follow-ups fail because they are "just checking in." The recipient's inbox has 30 other "just checking in" messages. The follow-up that gets a reply is the one that adds a new piece of context, a new data point, or a new reason to respond. Here is the prompt:

You are a B2B sales rep following up on a cold email that received no reply. Write a follow-up under 60 words.

ORIGINAL EMAIL: [paste the first email you sent]
DAYS SINCE: [3-5 days is the proven range]
NEW CONTEXT: [pick ONE: a relevant case study, a new trigger event, a short relevant insight, a question that reframes the original ask]
TONE: Even shorter and lower-friction than the first email. Assume the recipient is busy and skeptical. No "just wanted to bump this up" or "circling back."
CTA: Make the ask smaller. "Worth a 10-minute look?" beats "open to a 15-minute call?" A specific yes/no question beats an open-ended one.

Example Output

Subject: Re: 11% reply rate in 6 weeks

Hi Sarah,

One more data point since my last note — we just published the Replicant teardown with the exact prompt templates and sequencing. Took them from 4% to 11% in 6 weeks.

Worth a 10-minute look? If it's not a fit, I'll stop the sequence.

Best,
Alex

The pattern: new context (the teardown), smaller ask (10 minutes vs. 15), explicit out (stop the sequence). That last line is the most underrated move in cold email — giving the recipient permission to say no. It paradoxically raises reply rates because it signals confidence and reduces the perceived cost of responding.

3. Internal Update Prompt (Status Report / Weekly Recap)

Internal status emails are the most-written, least-read email in most companies. The reason: they bury the lead in 5 paragraphs of context that the writer needs but the reader does not. The fix is the "BLUF" pattern — Bottom Line Up Front, then supporting context. The prompt:

You are a team lead writing a weekly status email to your skip-level and 3 peers. Write under 200 words.

BLUF (1-2 sentences): The single most important thing that happened this week. State it as a result, not an activity. "Shipped the v2 onboarding flow, lifted day-1 activation from 38% to 52%" beats "Worked on onboarding."
WINS (3 bullets): The 2-3 things that went well, each with a metric or concrete outcome.
BLOCKERS (1-2 bullets): What is stuck and what you need to unstick it. Name the specific person or decision.
NEXT WEEK (2-3 bullets): The 2-3 priorities for next week, in priority order.
TONE: Direct, no hedging, no "I think we made good progress." Skip-levels and peers scan, not read.

Example Output

Weekly Update — Growth Team

BLUF: Shipped the v2 onboarding flow Tuesday. Day-1 activation lifted from 38% to 52% in 4 days, with no change to week-1 retention yet (data still early).

Wins:
- Activation experiment reached 95% statistical significance at n=4,200
- Closed 2 design hires (Riley, Sam) — start July 1
- Hit 91% of Q2 OKR commitment on new-user activation

Blockers:
- Need pricing-page redesign final review from Brand before Friday launch
- Engineering capacity on referral feature is 50% of plan — proposing we deprioritize to Q3

Next week:
- Launch pricing-page redesign (Friday)
- Ship referral program v1 if eng capacity holds, otherwise descope
- Kick off Q3 planning (offsite Mon-Tue)

Reply by EOD Friday if you want to change any of the above.

The structure: lead with the result, group by category, end with a clear reply deadline. The "reply by EOD Friday" line is the highest-leverage addition — it converts a status email into a decision-making artifact, which is what leadership actually wants.

4. Sales Proposal Email Prompt

Sales proposal emails fail for a predictable reason: they summarize the proposal instead of selling the decision. The recipient does not need a recap of the deck — they need a reason to act this week instead of next quarter. The prompt:

You are an account executive sending a post-demo proposal email. Write under 250 words.

RECIPIENT: [decision-maker role and title — the person who signs, not the user]
WHAT WE AGREED IN THE DEMO: [2-3 specific points — their pain, the use case they want to solve first, the success metric they named]
PROPOSAL SUMMARY: [3 bullet points — what they get in phase 1, what it costs, what the outcome looks like in 90 days]
RISK OF INACTION: [one sentence — what happens if they wait another quarter]
CTA: Specific next step with a specific date. "Sign by Friday to start the kickoff the following Monday" beats "Let me know what you think."
TONE: Confident, direct, no "I hope this proposal meets your needs." Treat the proposal as a done deal waiting for a signature, not a request for approval.
💡 The "risk of inaction" line: Most proposal emails bury the cost of doing nothing. The line that converts stalled proposals is the one that names the specific thing that will not happen if they wait — a missed quarter, a delayed launch, a competitor's announcement they will not be ready for. The risk has to be specific to their situation, not generic FOMO.

5. Customer Support Reply Prompt

Customer support emails fail for the opposite reason: they are too apologetic and not informative enough. The reader has a problem, has already waited 4 hours, and is scanning for an answer — not for "I sincerely apologize for the inconvenience." The prompt:

You are a customer support agent replying to a customer who is frustrated. Write under 180 words.

CUSTOMER ISSUE: [what is broken, in their words, not yours]
ROOT CAUSE: [what actually happened — bug, misconfiguration, policy gap, misunderstanding]
WHAT WE ARE DOING: [specific action, with a specific timeline — "fixing in the v2.3 release on July 5" beats "we are looking into it"]
WHAT THEY CAN DO NOW: [workaround, if any, or "nothing needed on your end, we have it"]
TONE: Warm, direct, no "I completely understand your frustration." Acknowledge the problem in one sentence, then move to the fix. Do not over-apologize — over-apologizing trains customers to expect a refund.

Example Output

Hi Marcus,

You are right — the export failed on rows 14,022 through 18,500. That is a known bug in the v2.2 release that we patched yesterday.

What we are doing: the fix is live in v2.3, deploying to your account automatically at 6pm PT today (in 4 hours). Once it deploys, re-run the export — it will complete all 18,500 rows.

What you can do now: nothing. Your data is intact on our side; the export is the only thing that failed.

I will send a confirmation the moment the fix deploys. If you want a direct line to me for the next 24 hours, my phone is below.

Best,
Priya
Customer Engineering

The structure: name the issue, name the fix, name the timeline, name the workaround (or "nothing needed"). The "direct line to me" addition is the move that turns a 1-star ticket into a 5-star review. The customer does not actually want to call you — they want to know they could if they needed to. FindSkill's research on AI email templates for customer service agrees: the emails that resolve tickets fastest are the ones that follow a six-part structure (situation, root cause, action, timeline, workaround, signoff) and skip the apology theater.

3 Email Prompt Mistakes to Avoid

Even with great templates, three patterns consistently produce bad emails. Catch them before you send.

Mistake 1: "I Hope This Email Finds You Well"

This phrase is the most-deleted opening line in email history. The recipient knows you do not hope that. The recipient knows you copy-pasted the line. The recipient has read it 200 times this week. Open with the specific reason for the email, not with a wish for their wellbeing. "Saw your post on reducing support response time" is a better opening. "Saw your post" is even better — the recipient's eyes will go to the next line to find out which post.

Mistake 2: Burying the Ask

The biggest reply-rate killer is the email that ends with "let me know if you have any questions" instead of a specific ask. "Any questions" is a question the recipient can answer with no action. A specific ask — "open to a 15-minute call next Wednesday at 2pm PT?" — requires a yes or a no. The easier the response, the more likely it is to happen. PhantomBuster's research on ChatGPT prompts for sales emails makes the same point: the most effective prompts use personalization tokens specifically to make the CTA specific to the recipient.

Mistake 3: Forgetting the P.S.

The postscript is the second-most-read line in an email (after the subject line). Use it. A P.S. with a specific proof point, a case study link, or a low-friction reframe of the ask will outperform the same content in the body. "P.S. The Replicant teardown is here if you want the data first" is a way to add value for the recipient who is interested but not ready to commit. The P.S. is also the right place for the "if not, tell me to stop" line that paradoxically raises reply rates.

Putting It All Together

The 5-part email prompt framework — role & recipient, context & hook, value proposition, ask, format & tone — is the spine. The five templates above are the muscle. The biggest reply-rate lever in any of them is specificity: the recipient's name, the trigger event, the specific outcome, the specific ask. Pick the template that matches the email, fill in the five parts with the recipient in mind, and let the AI handle the prose. One framework, five emails, no more "I hope this finds you well."

How to Create a System Prompt for Custom GPTs (Complete Guide)

Open the GPT Builder, type "make me a marketing assistant," and watch the most expensive part of Custom GPT creation go wrong in four seconds. The model happily writes a paragraph of friendly, vague, completely useless instructions that will haunt your GPT for the rest of its life. The reason is not the builder's quality — the builder is competent. The reason is that how to create a system prompt is a craft, not a fill-in-the-blank form, and the default builder output is the LLM equivalent of corporate lorem ipsum. A great system prompt has four distinct jobs to do, and a fifth one most builders forget. Get those four parts right and the same model that gave you "I am a helpful assistant that can help with marketing tasks" gives you a focused, on-voice, scope-limited, format-consistent tool that produces useful output on the first try and every retry after.

This guide is the full playbook. It is built on the 4-part anatomy of a production-grade system prompt — persona, scope, output contract, and failure modes — with the model-specific adjustments that make it work on ChatGPT's GPT-4o, GPT-4.1, and GPT-5. The structure is the same as the 5-part framework in our general prompt engineering guide, but applied to the long-lived "instruction" field that lives above every conversation, not the short-lived "user message" of a single turn. For the model-specific differences between ChatGPT, Claude, and Gemini, see Claude vs GPT-5 vs Gemini prompting; for the Claude-specific version of this anatomy, see 9 Tips to Write a Claude Prompt That Actually Works.

What a System Prompt Actually Is (and Is Not)

A system prompt is the invisible block of instructions the model reads before it reads the first user message. In a Custom GPT, it lives in the "Instructions" field of the GPT Builder. In the API, it goes in the system message of the messages array. Across all three, the job is identical: tell the model who it is, what it is allowed to do, what it is not allowed to do, and what shape the output should take — once, at the top of every conversation, for the entire life of the GPT.

That last part is the one most people miss. A system prompt is not a one-shot prompt — it is a long-lived behavior contract. Every conversation your user has with your Custom GPT, the system prompt is silently shaping the response. A vague system prompt does not just produce one bad answer — it produces thousands, multiplied by the number of users who will ever open that GPT. OpenAI's GPT builder guidance treats the instructions field as the single highest-leverage piece of the build, and the OpenAI Developer Community's "Custom GPT Limits" thread documents that the typical failure mode is not a weak model — it is a system prompt that delegates too many decisions to the model at runtime.

The 4-Part Anatomy of a Great System Prompt

Every system prompt that ships to production follows the same four-part structure. If you skip any of them, the model fills in the gap with its training-data default — which is generic, corporate, and on nobody's brand voice.

  1. Persona & Voice — who the model is, what it knows, what tone it uses, and what it is forbidden from sounding like. The single biggest mistake is the "helpful assistant" persona, which is the model's default and adds nothing.
  2. Scope & Capabilities — what the model is allowed to do, what it must always do (e.g., cite sources, ask for clarification, refuse off-topic requests), and what it must never do regardless of how the user phrases it.
  3. Output Contract — the exact shape of the response: format (markdown vs. plain), length (1 paragraph vs. 5 bullets vs. JSON), required sections, and what to do when the model does not know the answer.
  4. Failure Modes & Anti-Patterns — the specific bad behaviors the model tends to fall into on this task, and the explicit instruction to avoid them. This is the section most builders skip and the one with the highest quality lift.
💡 The "anti-patterns" section is the most under-used lever: CustomGPT.ai's research finds that system prompts with explicit "do not" instructions ("do not start with 'I hope this email finds you well'", "do not invent statistics") produce measurably better outputs than prompts that only describe what to do. The reason is that LLMs over-index on negative instructions — telling the model what to avoid is often twice as effective as telling it what to do, because the positive patterns are already in training data, but the negative ones are task-specific.

1. Persona & Voice: "Who Is This GPT, Exactly?"

The persona section answers "if this GPT were a person, who would they be?" The wrong answer is "a helpful AI assistant." The right answer is specific enough that you could draw a face: their expertise, their personality, their default tone, and the persona they are explicitly not. The OpenAI Developer Community thread on "Custom GPT Instructions" finds that 2nd-person ("You are…") and 3rd-person ("This GPT is…") both work, but 2nd-person produces slightly more consistent persona adherence because it reads as direct onboarding language to the model.

PERSONA:
You are a senior B2B copywriter with 12 years of experience writing
for early-stage SaaS companies. You have shipped copy for Notion,
Linear, and Figma in their first 100 customers phase. Your default
tone is direct, peer-to-peer, slightly opinionated, and allergic
to corporate jargon. You write the way a sharp founder would write
to another sharp founder.

YOU ARE NOT:
- A general "helpful assistant"
- A marketing agency voice (no "we leverage synergies")
- An academic voice (no "it is important to note that")
- A hype voice (no "this is a game-changer")

The "YOU ARE NOT" block is doing as much work as the "PERSONA" block. Without it, the model drifts toward its training-data average for "B2B copywriter" — which is the agency voice. The negative constraints are what keep the model on the persona you actually want.

2. Scope & Capabilities: What This GPT Does and Does Not Do

Scope is where most Custom GPTs fail silently. The model has no way to know what your GPT is "for" unless you say so, and no way to know what to refuse unless you tell it. A scope-less GPT will cheerfully help with anything, which means it will be useless at the one thing it was built for. The "Custom GPT Limits" research on OpenAI's community forum documents that the most common production failure is scope creep — the GPT drifts off-topic into a generic chatbot because the system prompt did not bound the domain.

IN SCOPE — you will help with:
- Landing page copy (hero, subhead, 3 benefit bullets, CTA)
- Cold email sequences (3-email cadence, 80 words per email)
- Pricing page copy (plan names, value props, FAQ entries)
- Sales one-pagers (problem, solution, proof, ask)

ALWAYS DO (no matter what the user asks):
- Ask 1 clarifying question if the request is vague
- Cite the specific input you used ("Based on the trigger
  event you gave, I opened with…")
- Produce 2-3 variants, not 1, for landing page and email

REFUSE / REDIRECT (do not do these even if the user asks):
- Do not write for B2C, ecommerce, or consumer brands
- Do not write in any language other than English
- Do not generate images, code, or anything outside copy
- Do not make up customer logos, statistics, or testimonials

The "ALWAYS DO" block is the part most builders skip. It is the difference between a GPT that follows your workflow and a GPT that invents its own. If your workflow requires the model to ask a clarifying question before writing, say so explicitly — the model will not infer it from the persona alone.

3. Output Contract: The Shape of Every Response

The output contract is the most underrated section. Most system prompts leave the response shape up to the model, and the model defaults to "a friendly paragraph of prose." For a copy GPT, that is the wrong format — the user wants variants, not a paragraph. For a code-review GPT, the user wants a diff. For a research GPT, the user wants a structured summary with citations.

OUTPUT FORMAT:
- Use markdown headings (##) for each deliverable
- Use bullet points for variants, not numbered lists
- Put the recommended option FIRST, then 2 alternatives
- End every response with "Want me to adjust the [tone |
  length | audience]?" — one line, never a paragraph

LENGTH:
- Landing page: 1 hero, 1 subhead, 3 bullets, 1 CTA, < 80 words
- Cold email: 3 emails, < 80 words each
- Pricing page: 3 plans, < 30 words per plan
- One-pager: 4 sections, < 200 words total

WHEN YOU DON'T KNOW:
- If the user has not given you enough input, ask 1
  clarifying question. Do not guess.
- If the user asks you to write for a brand you do not
  have information about, ask for the brand's existing
  copy as reference.
- Never invent statistics, customer logos, or product
  features.

The "WHEN YOU DON'T KNOW" sub-block is the single highest-quality section in the whole system prompt. Models hallucinate by default. Telling the model explicitly "never invent statistics" cuts the hallucination rate on that specific failure mode by a large margin in practice. The same principle applies to any other category the model is likely to make up: code, citations, customer names, dollar figures, dates.

4. Failure Modes & Anti-Patterns: Catch the Bad Habits Before They Ship

Every domain has its own failure patterns. For B2B copy, the model tends to: (1) start with "I hope this email finds you well," (2) bury the ask in the third paragraph, (3) invent product features, (4) end every email with "let me know if you have any questions." For a research GPT, the failure patterns are: citing papers that do not exist, summarizing the abstract instead of synthesizing, presenting the model's opinion as fact. For a tutoring GPT: giving the answer instead of guiding, using language above the student's level, skipping the worked example. Name them in the system prompt.

DO NOT:
- Open with "I hope this email finds you well" or any other
  empty pleasantries
- Use "in today's fast-paced world", "in the ever-evolving
  landscape", or "in the realm of"
- Use the word "leverage" as a verb
- End with "let me know if you have any questions"
- Use exclamation marks (they read as junior)
- Bury the CTA in the third paragraph — CTAs go in the
  last line, always
- Produce a single variant when the user asked for copy

CustomGPT.ai's research on production Custom GPTs finds that the anti-pattern block is the single biggest quality lift in a system prompt, because the model has seen every one of those bad patterns thousands of times in training data and needs an explicit instruction to override them. The patterns above are real, common, and exactly the kind of thing a copywriter would refuse to ship. The system prompt is the only place you can stop them at the source.

Putting It All Together: A Production-Ready System Prompt

Here is the complete system prompt assembled from the four parts above. It is around 250 words, which is the right size for a Custom GPT in this category — long enough to be specific, short enough that the model actually follows every line. Past 600 words, the model starts ignoring parts of the instructions; past 1,000, the effect is severe. If you find yourself past 600 words, you probably have a workflow problem (a chain of GPTs, or a system prompt plus a knowledge file) and not a system prompt problem.

PERSONA:
You are a senior B2B copywriter with 12 years of experience writing
for early-stage SaaS companies. You have shipped copy for Notion,
Linear, and Figma in their first 100 customers phase. Your default
tone is direct, peer-to-peer, slightly opinionated, and allergic
to corporate jargon.

YOU ARE NOT: a helpful assistant, a marketing agency, an academic,
or a hype voice.

IN SCOPE: landing page copy, cold email sequences, pricing page

ALWAYS DO: ask 1 clarifying question if the request is vague; cite
the specific input you used; produce 2-3 variants for landing pages
and email.

REFUSE: B2C, ecommerce, non-English, code, image generation, or
any request to invent logos/statistics/testimonials.

OUTPUT FORMAT: markdown, bullets for variants, recommended option
first, end with "Want me to adjust the [tone | length | audience]?"

LENGTH: landing page < 80 words, cold email 3x80 words, pricing
page 3x30 words, one-pager < 200 words.

DO NOT: open with pleasantries, use "leverage" as a verb, end with

Best Prompt for Coding: Debug Faster and Ship More with AI

Drop "write me a Python function" into ChatGPT, Claude, or Gemini and you get a wall of plausible-looking code with a stack trace waiting at the bottom. The function runs in the AI's head, not on your machine, and the AI defaults to whatever pattern it learned most often — which is rarely the pattern your codebase uses. A vague coding prompt hands the model every decision: language, framework, style, error handling, edge cases. A structured coding prompt hands the model only the decisions that matter: what the function does, what the input shape is, what the output should look like, and what the existing code already does. That is the difference between a 4-line bug hunt and a 4-hour one, and it is the difference between a 10x productivity claim that is real and one that is marketing copy.

This guide is the structured version. Four copy-paste prompt patterns that turn an LLM into a useful pair programmer: a "write new code" prompt that includes the right context, a "debug this error" prompt that hands over the stack trace, a "review my code" prompt that catches what you missed, and a "refactor this mess" prompt that preserves behavior while reducing complexity. Each pattern is built on the 5-part prompt structure from our general prompt engineering guide, tuned with the model-specific tweaks from our Claude vs GPT-5 vs Gemini comparison, and tested on Claude Code, Cursor, GitHub Copilot, and the ChatGPT/Claude/Gemini chat boxes. For the system-prompt version of these patterns — the long-lived "instructions" field that shapes every reply — see How to Create a System Prompt for Custom GPTs.

Why "Write Me a Function" Is Not a Coding Prompt

A coding prompt is a higher-context task than most people realize. To write a function that fits your codebase, the model has to know the language and version, the framework and version, the file's existing imports, the surrounding code style, the function's expected signature, the input validation rules, the error handling convention, the test framework, and the output format. That is 10 decisions the model has to make on every "write me a function" prompt — and every one is a coin flip toward the training-data default instead of your codebase.

Addy Osmani's prompt-engineering playbook is blunt: "AI pair programmers are powerful but not magical – they have no prior knowledge of your specific project or intent beyond what you tell them." His 2026 LLM-coding workflow finds that the most productive setups feed the model 2-3 reference files plus a 5-line spec. Without that context, the model writes textbook code that does not compile against your actual project.

The 5-Part Coding Prompt Framework

Every coding prompt should fill in all five parts below. Skip a part and the model will fill it in with its training-data default — which is the textbook answer, not the codebase answer.

  1. Context — the file path, the language + version, the framework + version, and any existing imports or helper functions the new code must work with.
  2. Goal — the user-visible behavior the code is supposed to produce, in one sentence. "Validate that an email looks well-formed and return the local-part" is a goal. "Write an email regex" is an implementation.
  3. Constraints — the non-negotiables: no external dependencies, must be O(n), must not mutate the input, must work on Python 3.11, must not log PII.
  4. Code Skeleton — the function signature, the docstring, or the failing test. The skeleton is the part most people skip, and it is the highest-leverage piece: it tells the model the exact shape the output must fit into.
  5. Format & Verification — what the response should look like (just the function, full file, a diff) and how the model should verify it (run the test, dry-run the regex, list edge cases checked).
💡 The 3-file rule: Paste in the file you are editing, the file you are importing from, and one test file. That is enough context for the model to match your style, avoid duplicate helpers, and write something that passes your existing tests.

That is the framework. The next four sections are the templates.

1. The "Write New Code" Prompt

The default failure mode of "write me a function that does X" is textbook code — a different style than your codebase, ignores your helpers, and adds a dependency you do not want. The fix is to anchor the model to your codebase before it writes a single line.

You are a senior [language] developer working in a [framework] codebase. Write a new function that fits the existing code style.

CONTEXT:
- File path: src/[path/to/file.py]
- Language: [e.g., Python 3.11, TypeScript 5.4]
- Framework: [e.g., FastAPI 0.110, Next.js 14]
- Existing imports already in the file: [paste the import block]
- Helper functions in scope: [paste 1-3 helper signatures with docstrings]

GOAL: [1 sentence — what the function should do from the user's perspective]

CONSTRAINTS:
- No new external dependencies (use only what's already imported)
- Must be O([n | log n | 1]) — explain why
- Must validate inputs and raise [ValueError | TypeError] with a specific message
- Must not mutate the input
- Must include a docstring with type hints

SKELETON:
[paste the function signature and docstring, OR a failing test that defines the contract]

FORMAT: Return ONLY the new function, no surrounding prose, no example calls.

VERIFICATION: After writing, list the 3 edge cases you handled and the 1 edge case you explicitly did not handle.

That prompt is longer than the typical "write me a function" prompt, and that is the point. The length is in the parts the model would otherwise guess: language version, framework version, existing imports, complexity budget, error convention, output shape. With those filled in, the model produces code that drops into the file.

2. The "Debug This Error" Prompt

The default failure mode of "why does my code crash" is a wall of plausible-sounding speculation. The model invents a story about what might be wrong, suggests 4 fixes, none of which work, and you lose 20 minutes. The fix is to hand over the actual error, the actual code, and the actual goal — the three things the model cannot guess on its own.

You are a senior [language] debugger. Diagnose a runtime error.

ERROR (full stack trace, last 15-20 lines):
[paste the traceback]

CODE (the smallest snippet that reproduces the bug):
[paste the function + the call site that triggers it]

GOAL: The code is supposed to [1 sentence — what it should do].

WHAT I ALREADY TRIED:
- [fix #1 you tried, and the result]
- [fix #2 you tried, and the result]

CONSTRAINTS:
- Do not guess — if you need more info, ask 1 specific question
- Identify the root cause, not a symptom
- If there are multiple plausible causes, rank them by likelihood

FORMAT: Return 1) root cause, 2) minimal fix, 3) why the minimal fix is correct, 4) what to add (a test, a log, a type hint) to prevent this class of bug in the future.

The "what I already tried" block is doing as much work as the error block. Without it, the model will suggest fixes you have already run. With it, the model skips the obvious ones and goes deeper. The "ask 1 specific question" constraint is the highest-leverage line in the whole prompt — it forces the model to admit when it does not have enough information, instead of confidently inventing a wrong answer.

🚀 The "minimal reproduction" rule: Most "why does this crash" prompts fail because the user pastes 200 lines of code when only 15 are relevant. Strip the snippet to the smallest code that still reproduces the bug, and the model can reason about it in one pass. If you cannot strip the snippet to under 30 lines, the bug is probably not where you think it is.

3. The "Review My Code" Prompt

The default failure mode of "review this" is a polite paragraph that says "looks good!" with maybe one nitpick. The model is trained to be agreeable, not critical, and a vague review prompt gets a vague polite review. The fix is to tell the model what kind of review you want, what to skip, and what to flag.

You are a senior [language] engineer doing a focused code review.

CODE (one function or one class, max 100 lines):
[paste the code]

REVIEW FOCUS (pick the 1-2 that matter for this change):
- Correctness: does it do what the docstring says, including edge cases
- Performance: any obvious O(n²) where O(n) would do, any unnecessary I/O
- Security: input validation, injection risks, secret leakage
- Readability: is the intent clear without comments
- Testability: can the core logic be unit-tested without I/O

SKIP:
- Style nits (formatting, naming) — those are for the linter
- Architecture — out of scope for a single-function review
- Praise — do not include "this is well-written" filler

FORMAT: Return a numbered list. Each item is one finding, in this format:
- **Line N**: [issue], **Fix**: [1-sentence patch], **Why**: [1-sentence why this matters]

CONSTRAINTS:
- If the code is correct and clean, say so in 1 sentence and stop
- Do not invent issues to fill the list — if you have 0 findings, return 0 findings
- Flag any case where the code is correct but the docstring is misleading

The "skip" block is the part most people leave out. Without it, the model spends its review budget on style nits and architecture. With it, the model focuses on the 1-2 things you actually care about. The "do not invent issues" constraint is the second-highest-leverage line — it counters the model's training to be agreeable and produces a shorter, more accurate review.

4. The "Refactor This" Prompt

The default failure mode of "refactor this code" is a rewrite that changes the behavior. The model decides that the function "should" do something slightly different, refactors toward that, and your tests start failing in subtle ways. The fix is to lock down the contract before the refactor: the tests, the inputs, the outputs, the side effects. Behavior is the spec; the refactor is the implementation.

You are a senior [language] engineer refactoring existing code. Behavior MUST NOT change.

CODE:
[paste the function, the class, or the 50-100 line block]

CONTRACT (do not change):
- Input: [exact input shape, including null/empty/edge cases]
- Output: [exact output shape]
- Side effects: [DB writes, logs, network calls, file I/O — list them all]
- Existing tests that must still pass: [paste 1-3 tests]

CODE SMELLS TO ADDRESS (pick from this list or add your own):
- [e.g., "the function is 80 lines and does 3 things — split it"]
- [e.g., "the same string is built in 4 places — extract a constant"]
- [e.g., "the for-loop with a flag variable — convert to a comprehension or early return"]

CONSTRAINTS:
- Do not change the public function signature
- Do not change the import block (use only what's already imported)
- Do not add new dependencies
- The refactored version must pass all existing tests unchanged

FORMAT: Return 1) the refactored code, 2) a 3-bullet diff summary (what changed and why), 3) a 1-sentence note on what you intentionally did NOT change.

The "what you intentionally did not change" line is the most underrated move. It tells the reviewer (and your future self) where the model noticed an opportunity but deliberately left it alone — usually because changing it would have required a contract change. The result is a refactor that is auditable in 30 seconds instead of 30 minutes.

3 Coding Prompt Mistakes to Avoid

Even with great templates, three patterns consistently produce bad AI code. Catch them before you ship.

Mistake 1: No File Context

The most common failure is asking for code without showing the file. The model writes textbook code that does not match your style, ignores your existing helpers, and uses a dependency you do not have. The fix is the 3-file rule: paste the file you are editing, the file you are importing from, and one test file.

Mistake 2: No Verification Step

The second most common failure is asking for code without asking the model to verify it. The model writes the function, says "here you go," and moves on. The fix is to add a verification line to every prompt: "After writing, list the 3 edge cases you handled and the 1 edge case you explicitly did not handle." That single line forces the model to think about the cases it just wrote.

Mistake 3: "Just Make It Work"

The third most common failure is asking the model to "just make it work" without specifying what "work" means. The model picks the most permissive interpretation, usually "the test I just invented in my head passes" — not the test that actually exists in your codebase. The fix is to anchor "work" to a specific artifact: a test that exists, a command that runs, a curl that returns 200, a regex that matches these 5 strings and rejects these 3. If you cannot name the artifact, you have not finished the spec.

Putting It All Together

The 5-part coding prompt framework — context, goal, constraints, code skeleton, format & verification — is the spine. The four templates above are the muscle. The biggest quality lever is the same one that shows up in the general prompt engineering guide: paste in the file, paste in the test, paste in the error. Three lines of context the model cannot guess are worth more than 30 lines of clever prompt engineering. Hand the model the right page, and it gives you a useful answer. Hand it the wrong page, and it gives you confident nonsense.

How to Write a Prompt for Data Analysis (Step-by-Step)

If you have ever pasted a CSV into ChatGPT, Claude, or Gemini and watched the model confidently invent columns, miscount rows, or "summarise" a trend that does not exist, you already know why finding the best prompt for data analysis is harder than it looks. Data is structured, model context is finite, and most off-the-shelf prompts assume the AI already understands your schema — it does not. A good data-analysis prompt is essentially a contract: it tells the model exactly which file to read, what shape the data has, what question to answer, and how to format the answer back.

This guide gives you that contract. You will get a four-part framework, four copy-paste templates, and the three mistakes that turn a 30-second prompt into a 30-minute cleanup job. By the end you will be able to go from a raw export to a chart, a summary, and an executive paragraph in a single turn — without babysitting the model.

Why Most Data Analysis Prompts Fail

Most failed prompts share the same three problems. First, they are vague about the schema. "Analyse this CSV" forces the model to guess what each column means, what the unit of analysis is, and which columns are even relevant. Second, they ask for everything at once — totals, trends, outliers, forecasts — and the model has to pick what to skip. Third, they do not specify an output format, so you get a wall of prose instead of a table you can paste into a slide.

The fix is structural, not stylistic. A useful rule of thumb: every data prompt should answer four questions before the model ever runs — Source, Columns, Aim, Format. We will turn that into a reusable framework below.

The 4-Part Framework: S.C.A.F.

S.C.A.F. stands for Source, Columns, Aim, Format. It is the minimum viable brief for any data-analysis task, and it works with every major model. Each part serves a specific failure mode:

  • Source — tell the model which file or table, and how rows are organised. Prevents the "I see no data" or "I'm using a generic example" replies.
  • Columns — list the columns you care about and what they mean. Prevents the model from averaging the wrong field or misreading a date as a number.
  • Aim — state the business question in one sentence. Prevents the "here is a broad overview" non-answer.
  • Format — specify the output shape: table, bullet list, JSON, code, chart description. Prevents the prose blob.

You can read more about how the core prompting principles feed into this in our foundational guide. S.C.A.F. is what data analysis looks like once those principles meet a real table.

Template 1 — The Clean-CSV Explainer

Use this when the model has never seen the file before and you need a sanity check before doing any real analysis. It primes the model with the schema and forces a small, auditable response.

Role: You are a data analyst reviewing an unfamiliar CSV.

Source: The file `orders_2025.csv` has one row per order, with a header row.
Columns:
- order_id (string, unique)
- order_date (ISO 8601, e.g. 2025-03-14)
- customer_id (string)
- channel ('web', 'app', 'retail')
- total_usd (number, two decimals)

Aim: Confirm you understand the file, then flag anything odd.

Format:
1. A 3-bullet summary of what the dataset appears to contain.
2. A short list of quality issues (missing values, weird types, suspicious ranges).
3. Ask me one clarifying question before we go further.

Do not run any analysis yet. Do not invent columns I did not list.

This is the cheapest step in the whole pipeline, and it catches most "the model hallucinated the schema" disasters before they compound. If you want a deeper intro to role-prompting, see our 9 tips for better Claude prompts.

Template 2 — The Quick-Stats Auditor

Use this when you need a fast descriptive pass: counts, averages, distributions, top-N. The trick is asking for the recipe first, not the numbers — the model can be wrong about the recipe, but you cannot catch it if you skip that step.

Source: Same `orders_2025.csv`. Rows: ~50,000.
Columns in use: order_date, channel, total_usd.

Aim: Produce a quick descriptive audit of 2025 sales.

Step 1 — Show the exact pseudocode (pandas or SQL) you would run to compute:
  a) total revenue
  b) revenue by channel
  c) monthly revenue trend
  d) top 10 orders by total_usd

Step 2 — Run the pseudocode mentally on the schema and report the
results as a small markdown table.

Step 3 — Flag any step where the schema is ambiguous enough that
the real numbers could be off by more than 5%.

Format: Three sections, clearly labelled. No prose preamble.

Asking for the recipe first means you can sanity-check the logic in 10 seconds, and the model is far more careful when it knows the recipe is part of the deliverable.

Template 3 — The Insight Generator

Use this once the descriptive audit is clean and you want the "so what". The risk here is generic insight — "revenue is trending up" is not an insight. The fix is to demand comparison, magnitude, and a counter-hypothesis.

Source: `orders_2025.csv` (full year, ~50,000 rows).
Context: 2024 revenue was $4.1M. We are mid-2025 and the CFO wants
a read on whether we are on track, behind, or ahead — and why.

Aim: Produce 3 to 5 non-obvious insights, not a recap.

For each insight, output exactly:
- **Headline** (one sentence, under 18 words)
- **Evidence** (the numbers, with comparison to 2024 or to plan)
- **Why it matters** (one sentence on the business implication)
- **Counter-hypothesis** (one alternative explanation I should test)

Format: Bullet list, no preamble. Skip insights you cannot support
with a number from the file.

The "counter-hypothesis" line is what separates a junior prompt from a senior one. It forces the model to argue with itself, which dramatically reduces the kind of confident-but-wrong findings that erode trust. Researchers have shown that structured prompt patterns can cut hallucination rates by up to 36% — the counter-hypothesis step is a small version of that idea.

Template 4 — The Executive Summary

Use this last. Once the audit and insights are solid, distil everything into a single paragraph a non-technical reader can act on. This is the prompt most teams skip, and it is usually the one their boss actually wants.

Source: The audit table and insight bullets you just produced.
Audience: CFO, 90 seconds to read, no tolerance for jargon.

Aim: Write a 4-sentence executive summary.

Sentence 1: Headline finding (are we on track, and by how much).
Sentence 2: The single biggest driver behind it.
Sentence 3: The one risk that could change the answer.
Sentence 4: The one decision you want from me.

Constraints:
- Plain English, no acronyms, no bullet points.
- Every number must trace back to the audit or insights above.
- If any number is uncertain, say so in one phrase, do not hide it.

Notice that this prompt does not give the model any new data. The value is in the constraint layer: audience, length, structure, and a hard rule against invented numbers.

3 Mistakes to Avoid

1. Skipping the schema brief. If you do not tell the model what each column means, it will guess — and the guesses are usually plausible enough to slip past a quick read. The 60 seconds you spend on the brief save ten minutes of forensic debugging. Real users regularly report that models "can't figure out where the duplicates are, and it just completely hallucinates results" when fed raw CSVs with no schema context.

2. Asking for analysis and format at the same time. "Give me a table showing revenue by channel with a 2-line summary and a chart" is three jobs in one. Pick one. Tables for the audit, bullets for the insights, prose for the summary. Trying to do all three in a single turn is the most common reason a prompt hits the model's context window and degrades into vague output by the end.

3. Trusting the first number. Always run the audit, then the insights, then the summary — in that order, with a human spot-check between steps. The Wharton AI Analytics team recommends this exact pattern: "Start with a simple prompt like: 'I'd like to analyze my customer, orders, and returns data. Please load each CSV file.'" That small, verifiable first step is what makes the rest of the chain trustworthy.

Put It All Together

The full S.C.A.F. pipeline looks like this:

  1. Clean-CSV Explainer — confirm the model understands the file.
  2. Quick-Stats Auditor — get the numbers, with the recipe visible.
  3. Insight Generator — turn numbers into findings, with counter-hypotheses.
  4. Executive Summary — distil everything into a 4-sentence brief.

For most business datasets, all four steps run in a single chat session and take under five minutes. The output is auditable, the numbers trace back to the file, and the model has been forced to argue with itself at every step. That is what makes a prompt the best prompt for data analysis — not cleverness, but structure. Best Prompt for Social Media: 8 Templates That Drive Engagement

Why Most AI Social Media Posts Fall Flat

If you've ever pasted a topic into ChatGPT and posted the first result on LinkedIn, you already know the outcome. The caption sounds like everyone else's. The hook is a breathless "Let's dive in 🔥." The CTA is "Thoughts?" with a single emoji. According to CampaignSwift's agency research, "the difference between mediocre AI output and content your clients approve on the first round" is almost always prompt structure, not model quality. With ChatGPT now reaching 900 million weekly active users as of February 2026 (up 125% year-over-year, per OpenAI via Reuters), the feed is flooded with default-style posts. The only way to stand out is to feed the model the brief it actually needs: voice, platform, format, and a measurable goal.

This guide gives you eight best prompt for social media templates — two each for Instagram, LinkedIn, Twitter/X, and TikTok — that you can paste into ChatGPT, Claude, or Gemini and customize in under two minutes. Each template follows a consistent block structure (Role, Context, Task, Format, Constraints, Self-check) so the model always knows what to produce. By the end you'll have a reusable library you can adapt to any client, brand, or campaign.

The Anatomy of a Winning Social Media Prompt

Before the templates, it helps to understand the structure they share. A good social media prompt is not a single sentence — it's a brief. Treat the model like a junior copywriter who knows nothing about your brand, your audience, or this week's campaign. The six blocks below appear (in slightly different forms) in every template that follows.

  • Role: "You are a senior social media copywriter specializing in [platform]…" — primes the model's voice and vocabulary.
  • Context: brand voice (3 adjectives), audience (job title + pain point), product/offer, and the campaign's single goal.
  • Task: one specific deliverable. "Write 3 caption variations" — not "help me with Instagram."
  • Format: length in words or characters, structure (hook → body → CTA), hashtag count, emoji count.
  • Constraints: words to avoid ("delve," "unleash," "game-changer"), forbidden claims, brand compliance rules.
  • Self-check: ask the model to rate its own output 1–10 on hook strength, clarity, and on-brand tone. Low scores trigger a rewrite before you ever see the draft.

This is the same D-E-T-H skeleton (Define perspectives, Establish success metrics, Task breakdown, Human feedback loop) that emerged from a 1,000-prompt test in r/PromptEngineering — and it transfers cleanly to social copy.

Instagram Caption Templates

Instagram captions live or die in the first 125 characters — that's what shows before the "more" tap. Every prompt below explicitly asks for a hook line, a body, and a CTA, plus the platform's character sweet spot.

Template 1 — Instagram Carousel Caption (Educational)

Use this when you're posting a 7–10 slide educational carousel and want saves and shares, not vanity likes.

You are a senior Instagram copywriter for [BRAND], a [INDUSTRY] brand whose tone is [3 ADJECTIVES, e.g. "warm, evidence-based, lightly witty"].

Context: Our audience is [JOB TITLE / LIFE STAGE] who struggle with [PAIN POINT]. This carousel teaches them [ONE SPECIFIC OUTCOME, e.g. "how to negotiate a 15% raise in 3 messages"]. The campaign goal is saves, not likes.

Task: Write 1 Instagram caption for a 7-slide carousel.

Format:
- Hook line (≤125 chars, no emoji lead, must stop the scroll)
- 2 short body paragraphs (≤40 words each) explaining the value
- CTA: "Save this for the next time you [TRIGGER]" + 5 niche hashtags
- Total caption length: 150–220 words

Constraints: No "delve," "unleash," "in today's fast-paced world." No more than 3 emojis total.

Self-check: Rate the caption 1–10 on hook strength, clarity, and on-brand tone. If any score is below 8, rewrite once.

Template 2 — Instagram Reel Script (Authority)

Reels need a script that survives a 1.5-second swipe-away. This template is built for thought-leadership Reels between 15 and 30 seconds.

You are a Reels scriptwriter who specializes in 15–30 second authority-building clips for [NICHE].

Context: I'm a [ROLE, e.g. "fractional CFO for SaaS startups"]. I want to share one contrarian take about [TOPIC] that will make my ideal client — [ICP, e.g. "founder doing $1–5M ARR"] — save the Reel and DM me.

Task: Write 1 Reel script with on-screen text overlays.

Format:
- Pattern interrupt (first 1.5s, ≤8 words, no "Hey guys")
- 3 short spoken lines, each ≤12 words
- One specific data point or named example
- Closing line that sets up a save/share

Constraints: Total spoken word count ≤55. No hashtag list in the script (those go in the caption). Avoid motivational clichés.

Self-check: Would a stranger keep watching past second 2? Score 1–10 and rewrite if below 8.

LinkedIn Post Templates

LinkedIn rewards specificity, structure, and a clear point of view. A 2025 Forbes article noted that "most people under-prompt or over-edit ChatGPT and that's why the posts feel off" — these templates fix both halves.

Template 3 — LinkedIn Text Post (Story-Proof)

The "I learned this the hard way" format still works on LinkedIn — when it's authentic. This prompt forces the model to base the story on a real moment you provide.

You are a ghostwriter for a [INDUSTRY] executive. Their tone is [3 ADJECTIVES, e.g. "direct, generous, dry"]. They post 3x per week on LinkedIn to attract [ICP, e.g. "Series A founders"].

Context: The executive had this real experience: [PASTE 2–3 SENTENCES OF THE ACTUAL STORY — what happened, when, who was involved]. The lesson they want to teach is [LESSON].

Task: Write 1 LinkedIn post (1,200–1,500 characters) using the story as proof of the lesson.

Format:
- Line 1: a contrarian or specific claim, not a greeting
- Line 2: a single blank line (LinkedIn formatting hack)
- Body: 5–8 short lines, each its own paragraph, with one-line reveals
- Final line: a question to the reader, no CTA like "like and share"

Format:
- Slide 1: bold claim, ≤6 words

The 3 Mistakes 99% of People Make With AI Social Posts

After reviewing hundreds of AI-generated social posts, the failure modes are remarkably consistent. A Forbes piece on AI in social media campaigns lists 15 common mistakes; three of them explain most of the bad output you see.

  1. Posting the first output verbatim. The first generation is the model's average answer, not your best answer. Always run the self-check step in the templates above, then rewrite the lowest-scoring block manually.
  2. Skipping platform-specific format. A LinkedIn post is not a Twitter thread is not an Instagram caption. Templates 1–8 each specify length, structure, and constraints — that specificity is what makes the output usable.
  3. Ignoring brand voice constraints. Generic "engaging, professional" descriptions produce generic output. The 3-adjective voice block (Templates 1, 2, 3) and the forbidden-words list are the cheapest, highest-impact additions you can make.

A 2025 LinkedIn analysis by Team Lewis added a fourth worth keeping in mind: shouty title formatting (alternating caps, three exclamation points, emoji chains) doesn't read as confident — it reads as insecure. Use emoji with intent, not as decoration.

How to Adapt These Templates to Any Brand

The eight templates are scaffolds, not scripts. Three small adjustments turn them into a reusable system for any client or campaign.

  • Create a "voice card" you paste into the Context block. Three adjectives, one sentence on what the brand never does, and one sentence on what the brand always does. Save it as a snippet in your notes app.
  • Keep a "do not say" list. Five to ten words or phrases the brand avoids. Add to it every time you edit an AI draft. Over time this list is what differentiates your output from everyone else's.
  • Score, don't rewrite. Use the self-check step. If the model scores itself 8+, post with light edits. If it scores below, send the prompt back with one extra line of constraint — don't write the post yourself from scratch.

Best Prompt for Resume Writing: Stand Out in 2026 ATS

Why a Generic "Write My Resume" Prompt Fails

Most people open ChatGPT, type "write me a resume for a software engineer role", and get back a generic college-career-center handout. The problem isn't the model — it's the best prompt for resume being the wrong one. The model got three nouns and no constraints, so it produces a generic doc — one that lands in the 75% of resumes that ATS systems reject before a human ever opens it.

The fix is the 5-part prompt framework. Specify the role you want the model to play, the raw material it should rewrite, the target job, the output contract (length, format, tone), and the anti-patterns it must avoid. This article gives you 4 copy-paste prompts built on that framework, plus the 3 mistakes that ship a resume straight to the rejection pile.

The 3-Second Rule: What an ATS Actually Does

An ATS doesn't "read" your resume. It parses the file, extracts fields, and scores the document against the job description on three axes: keyword match, recency, and formatting integrity. A 2026 CVCraft study of Fortune 500 hiring pipelines found that resumes matching 60%+ of job keywords pass ATS screening 90% of the time, while the average unoptimized resume scores around 55%.

That 55%-to-90% gap is exactly what a good prompt closes. The LLM is your keyword-stuffing assistant; the recruiter phone screen is where you actually get hired. So the goal is not "write a perfect resume" — it is "produce a doc the ATS forwards to a human."

The Framework: 5 Parts Every Resume Prompt Needs

Every prompt below follows this 5-part skeleton. Skip any one and the output degrades.

  1. Role. "You are a senior technical recruiter with 12 years of experience screening resumes for FAANG-tier companies" is dramatically better than "act as an expert."
  2. Raw material. Paste your actual job history and skills. The model can't invent experience you didn't give it — but it can rewrite what you have at a higher level of clarity and impact.
  3. Target job. Paste the full job description. The LLM extracts keywords, required skills, and seniority signals and aligns your existing bullets to them.
  4. Output contract. Specify length, format, tone, and structural rules (reverse-chronological, no tables, no headers).
  5. Anti-patterns. List what the model must NOT do: no fabricated metrics, no buzzword stacking, no invented tools, no first-person pronouns. The difference between passing the phone screen and getting caught in a lie.

That 5-part skeleton is the same prompt-engineering thinking behind our general prompt-engineering guide — applied to a domain where the cost of a bad output isn't a mediocre blog post, it's a 6-month job search.

Prompt 1: The From-Scratch Resume

Use this when you have a rough job history (LinkedIn export, old resume, brain dump) and want a clean v1 you can iterate on.

You are a senior technical recruiter with 12 years of experience screening resumes for top-tier tech companies. Your job is to rewrite the candidate's raw career history into an ATS-optimized 1-page resume tailored to a specific target role.

ROLE: Senior Backend Engineer (Python, distributed systems, 5+ years experience)

RAW MATERIAL:
- Current title: Software Engineer II at Acme Payments (2022–present)
  * Built a Kafka pipeline processing 4M events/day for fraud detection
  * Reduced p99 API latency from 850ms to 120ms via query batching
  * Mentored 2 junior engineers; ran the on-call rotation for 18 months
- Previous: Software Engineer at Beta Logistics (2020–2022)
  * Migrated monolith to microservices on Kubernetes, cut deploy time 60%
  * Owned the inventory sync service, integrated with 3PL APIs
- Skills: Python, Go (working), PostgreSQL, Redis, Kafka, AWS (ECS, Lambda, S3), Terraform, Datadog
- Education: BS Computer Science, State University, 2020

TARGET JOB: [paste full job description here]

OUTPUT CONTRACT:
- 1 page, plain text, no tables, no columns, no headers
- Reverse-chronological order
- Each role: company, title, dates, then 3–5 bullets
- Bullets start with strong action verbs (Built, Reduced, Owned, Migrated, Led)
- Quantify impact wherever the raw material supports it (do not invent numbers)
- No first-person pronouns, no "I", no "my"
- Skills section at the bottom as a comma-separated list

ANTI-PATTERNS — DO NOT:
- Fabricate metrics, certifications, or tools the candidate did not list
- Add generic "team player" / "hard worker" / "passionate" filler
- Invent company names, titles, or dates
- Use tables, text boxes, graphics, or any element that breaks ATS parsing
- Include a photo, age, marital status, or any non-US/EU standard field

Return the finished resume plus a 3-bullet "keyword alignment" note showing which target-job keywords you used and where.

The "keyword alignment note" line is the most underrated part. It forces the model to show its work on the axis the ATS scores you on, and you can audit it against the job description in 30 seconds.

Prompt 2: The Bullet-Point Polish

Your bullets read like a job description ("Responsible for managing the API team") instead of an impact statement ("Led a 4-engineer API team, shipped 12 services, owned 99.95% SLO"). This prompt upgrades bullets without rewriting the whole document.

You are a resume-writing specialist who rewrites weak duty-statements into strong impact-statements using the XYZ formula: "Accomplished [X], as measured by [Y], by doing [Z]."

Rewrite the bullets below. For each input bullet, output:
1. The rewritten bullet (1 line, max 25 words, starts with a strong past-tense verb, quantified where possible)
2. A 1-sentence "why this works" note pointing out the structure (action, metric, scope)

DO NOT:
- Add metrics the original does not support (use "[ADD METRIC]" as a placeholder if a number is missing)
- Change the underlying meaning of what the candidate did
- Use present tense for past roles
- Stack adjectives ("highly motivated", "results-driven", "passionate")

INPUT BULLETS:
- "Responsible for the customer onboarding flow"
- "Worked on improving database performance"
- "Helped migrate the codebase to a new framework"
- "Was part of the team that built the analytics dashboard"
- "Did code reviews and mentored junior developers"

The XYZ formula forces the LLM to commit to a measurable outcome — the single biggest signal a senior recruiter scans for. Even when the input is vague, the model must find a real metric or flag a "[ADD METRIC]" placeholder, never invent.

Prompt 3: The Cover-Letter Companion

A resume tells the ATS you match; a cover letter tells the recruiter why. Run this prompt with Prompt 1 against the same target job for a complete packet.

You are a hiring manager who has read 10,000 cover letters and now auto-rejects 95% of them in the first 2 sentences. Write a 3-paragraph cover letter for the candidate below that you would actually read past the first line.

STRUCTURE:
- Paragraph 1 (2–3 sentences): A specific, falsifiable claim about why THIS company, not a generic "I'm excited to apply." Reference a recent product launch, engineering blog post, or strategic move.
- Paragraph 2 (3–4 sentences): One concrete project from the candidate's history that maps to the job's hardest requirement. Quantify if possible.
- Paragraph 3 (2–3 sentences): A short close with a single low-friction ask (a 20-minute intro call, not "the opportunity to discuss my background further").

TONE: Confident, specific, no buzzwords. Read like a human wrote it at 9pm on a Tuesday, not a LinkedIn AI assistant at 3am.

CANDIDATE RAW MATERIAL: [paste same as Prompt 1]
TARGET JOB: [paste full job description]

ANTI-PATTERNS — DO NOT:
- Open with "I am writing to express my interest in..."
- Use "passionate", "driven", "synergy", "leverage", or "dynamic"
- Restate the resume; reference one project and go deep
- Exceed 250 words total
- Include "References available upon request" (it's 2026; nobody says this)

The "no buzzwords" line does heavy lifting. LLMs default to corporate-speak (the training data skews that way); banning the top 5 overused words cuts the "AI-generated smell" by roughly half — the difference between a letter a recruiter reads and one they skim.

Prompt 4: The ATS Score Audit

Before you submit, run your existing resume + target job through this prompt. It simulates what an ATS does and tells you exactly which keywords you're missing.

You are an ATS parser modeled on Greenhouse and Lever. Score the resume below against the target job description on these axes:
1. Keyword match (0–100%): which job-description keywords appear in the resume, which are missing?
2. Formatting integrity (pass/fail): any tables, columns, headers, graphics, or non-standard sections that would break parsing?
3. Recency weighting (0–100%): does the most recent role get the most detail and the most senior bullet?
4. Length appropriateness (0–100%): is it 1 page for under 10 years experience, 2 pages for senior/principal?

OUTPUT FORMAT:
- Overall ATS score (0–100)
- Top 5 missing keywords ranked by importance
- 3 specific bullet-level edits that would raise the score by 10+ points
- A "do not submit" verdict if formatting integrity fails

RESUME: [paste your current resume]
TARGET JOB: [paste full job description]

This prompt is your last-mile QA. It catches the formatting traps (a 2-column sidebar that parses as garbage), keyword gaps ("Kubernetes" vs "k8s"), and recency inversion (first job with 5 bullets, current with 2). Run it before every application.

The 3 Mistakes That Ship a Resume to the Rejection Pile

These three failure modes come up in every coaching session — the real reason "I used ChatGPT and still didn't hear back."

Mistake 1: Letting the model invent experience. The most common ChatGPT resume failure. You paste a thin job history, the model fills the gaps with plausible-sounding but fabricated metrics. A senior recruiter asks about that 40% in the phone screen. You have no idea where it came from. The conversation ends. Fix: the anti-patterns section of every prompt above explicitly bans fabrication. Replace anything you can't defend with "[ADD METRIC]" or a real number.

Mistake 2: Skipping the target-job description. A resume that isn't tailored to a specific job is a lottery ticket. Skipping the target-job field — and pasting your generic resume into Prompt 1 with the job-description placeholder unfilled — is the most common cause of a 55% ATS score. Fix: paste the full job description. Every time. No exceptions.

Mistake 3: Pretty formatting that breaks ATS parsing. The "fancy" resume template The "fancy" resume template with the two-column sidebar, colored header, and skill icons looks great in the PDF preview and parses as zero fields in the ATS. Fix: use a single-column plain-text template, or run Prompt 4 to audit the formatted version before submitting. The 60% of rejections that are formatting-related (per Resume Optimizer Pro 2026) are entirely preventable.

Putting It Together: The 15-Minute Application Workflow

Workflow per application: (1) run Prompt 4 against your current resume to get the ATS score; (2) run Prompt 1 with the target job and raw material; (3) run Prompt 3 for the cover letter; (4) re-run Prompt 4 on the new resume to confirm 85%+. Total: 15 minutes, vs. an hour and worse output before.

The win is reuse: build the raw material once, keep the prompts in a doc, and every application becomes a 15-minute iteration loop. Same leverage as the email-writing prompts — once a template works, the marginal cost of the next application drops to near zero.

Best Prompt for Storytelling: 6 Frameworks That Hook Readers

Writing a short story from a single line of inspiration is a craft problem, not a magic problem. The gap between "what if a librarian can read memories?" and a 5-page short story with a hook, a midpoint turn, and a payoff is mostly structure. The best prompt for storytelling is a frame the model can hang the rest of the story on — not a magic spell.

Six frameworks below turn a one-line idea into a structured short story without the AI collapsing into generic prose. Each one is named (Save the Cat, Fichtean, Hero's Journey, In Medias Res, Seven-Point, Pixar's 4-sentence), each one ships with a copy-paste template, and each one ends with the same 20-minute revision loop you can run on any AI draft.

Quick answer: The best prompt for storytelling is a 3-layer prompt: (1) one-line concept, (2) a named story framework (Save the Cat, Fichtean, Hero's Journey, etc.), (3) explicit constraints — POV, tense, length, voice, and a banned-words list. Combine these three and the model produces a draft you can revise in 20 minutes instead of 3 hours.

1. Why "write me a story" prompts fail

The default response to "write me a story" is a story-shaped object — opening, rising action, climax, denouement. The shape is correct, but the story is usually forgettable: generic characters, no sensory detail, dialogue that sounds like a stage play rather than two people arguing about the rent. The model has filled the structure with the most statistically common choices, so every other person who prompted the same way got a near-identical story.

A r/WritingWithAI user put it well: "AI drafts massively, in compliance with a Canon you build. The bottleneck is not the prompt." The Canon is the named framework, the constraint set, the character bible, the world rules. Once you build it, the model can draft 20 chapters in 96 minutes — one user generated 137,806 characters (~70K words) of an ongoing series with 89 parallel sub-agents and an 87.5/100 internal consistency score. The model isn't the bottleneck. The Canon is.

So the goal of the first prompt is to build a small Canon: a named framework, a POV, a setting, and a protagonist with one specific wound or want. Everything else cascades from that.

2. The 3-layer storytelling prompt template

Every framework below uses the same 3-layer structure. Memorize this once and reuse it for short stories, novel chapters, screenplays, and game dialogue — the bones are identical.

  1. Layer 1 — Concept: A one-line idea with a specific tension. "A short story about [CONCEPT] — protagonist is [NAME, age, one trait, one wound]."
  2. Layer 2 — Framework: A named structure. "Use the [FRAMEWORK NAME] structure. Required beats: [3-5 beats]."
  3. Layer 3 — Constraints: POV, tense, length, voice, banned clichés, opening image, ending payoff.
Layer 1 — Concept:
"A short story about [CONCEPT in one line, with a specific tension]. The protagonist is [NAME, age, one trait, one wound]."

Layer 2 — Framework:
"Use the [FRAMEWORK NAME] structure. Required beats: [list 3-5 beats with one-line definitions]."

Layer 3 — Constraints:
- POV: [first person / close third / omniscient]
- Tense: [past / present]
- Length: [target word count]
- Voice: [3 adjectives, e.g. "dry, observational, 1980s"]
- Banned: [2-3 words or phrases, e.g. "shivers down spine, in this world, little did they know"]
- Open with: [a specific image or line of dialogue, not weather or waking up]
- End with: [a one-line payoff, not a moral]

The model has to make 15-20 small decisions for every short-story prompt. Each compounds — the more specific the choices, the less the output looks like training data. Specificity is the only defense against generic AI fiction.

3. Framework 1: Save the Cat (15 beats, modern pacing)

Save the Cat by Blake Snyder is a screenwriting beat sheet that maps cleanly to short fiction. The 15 beats are too granular for a 2,000-word story, so collapse them to the 7 most useful: Opening Image, Catalyst, Debate, Break Into Two, Midpoint, Bad Guys Close In, Final Image. That gives the model a pacing arc without forcing a novel-length structure.

Concept: A retired astronaut agrees to one last mission — but only because the new captain is the daughter of the colleague who died in her last mission.

Write a 2,000-word short story using Save the Cat (7 beats).

Concept: Retired astronaut. New captain = daughter of dead colleague.

Beats:
1. Opening Image — protagonist alone, specific object, not generic
2. Catalyst — mission offer arrives, unexpected
3. Debate — almost says no, then accepts
4. Break Into Two — she steps onto the ship
5. Midpoint — reversal: the daughter is not who she thought
6. Bad Guys Close In — a decision with no good answer
7. Final Image — quiet, specific, not a moral

Constraints: close third, past tense. Voice: restrained, technical, working-class.
Banned: "little did she know", "shivers", "in this world".
Open with: the sound of the coffee machine, not her thoughts.
End with: a one-line payoff that circles back to the opening image.

Why this works: The 7 beats are explicit, the concept has built-in tension, and the banned-words list forces the model to do the sensory work instead of reaching for clichés. The "circles back to the opening image" instruction is the single most useful closing line you can add — it forces structural symmetry.

4. Framework 2: Fichtean curve (rising crises, no setup)

The Fichtean curve is the opposite of the Hero's Journey. No exposition, no ordinary world, no setup. Drop the reader into the third crisis, then escalate. Three to five rising crises, each worse, until the climactic fifth. No falling action — the story ends on the crisis peak. Good for thrillers, horror, and stories that open in motion.

Concept: A locksmith gets a call to open a safe in a house where the previous owner disappeared two weeks ago. The first thing wrong is the safe is in the wall behind the refrigerator.

Write a 1,800-word story using the Fichtean curve.

Concept: Locksmith, missing owner, safe behind the fridge.

Crises (escalate each):
1. Combination is wrong for the lock type
2. There's something behind the safe
3. Previous owner is on the news, alive
4. Locksmith's house key doesn't fit his own door anymore
5. Climactic choice: open the safe, or walk away

Constraints: first person, present tense. Voice: dry, observant, cynical.
Banned: explaining the supernatural.
Open with: a phone call, no greeting.
End with: the locksmith's hand on the safe dial, mid-turn.

Why this works: The 5 crises are escalating, not repeating — each one raises the stakes. The "mid-turn" ending is a deliberate cliffhanger: the climax is the decision, not the outcome. Use this for genre fiction where motion matters more than character.

5. Framework 3: Hero's Journey (compressed for short fiction)

The Hero's Journey (Campbell, then Vogler) is 12 stages. For a short story, compress to 5: Ordinary World, Call, Threshold, Ordeal, Return. Skip the Refusal of the Call, the Mentor, the Atonement. The 5-stage version is the backbone of most published short fiction that uses the framework at all.

The Hero's Journey is the easiest framework to write badly with AI because the model defaults to fantasy or sci-fi. Force a mundane setting. The test: can the model write a Hero's Journey in 1994 Ohio without summoning a dragon? If yes, the prompt works.

Concept: A 12-year-old in 1994 rural Ohio has to deliver a letter across town in one afternoon for a neighbor who can't leave the house. The letter is sealed.

Write a 2,200-word story using the 5-stage Hero's Journey.

Concept: 12-year-old, 1994 Ohio, deliver a sealed letter across town.

Stages:
1. Ordinary World — specific day, specific chore
2. Call — the neighbor asks, refuses to explain
3. Threshold — leaves the yard, crosses the main road
4. Ordeal — a test that reveals the letter's purpose
5. Return — home, changed in one small specific way

Constraints: first person, past tense. Voice: 1994 working-class Ohio, no anachronisms.
Banned: wise-beyond-years narrator voice.
Open with: the sound of the screen door.
End with: the neighbor's reaction, not the kid's.

Why this works: The "mundane setting test" is the only way to prevent the model from falling back on training-data fantasy. The 5-stage compression is short enough for a single prompt context but rich enough to give the model structure. For more on how to set those mundane-setting constraints, see the prompt engineering guide.

6. Framework 4: In Medias Res (open at the midpoint)

In Medias Res is a technique, not a full framework. Open the story in the middle of an action, then flash back to explain. The 5-prompt version: Opening Scene, Trigger Flashback, Rising Action, Return to Present, Resolution. The model is forced to write two timelines and tie them at the end.

Concept: A translator at the UN is mid-sentence into a microphone when she hears her brother's voice in her headset — the brother who disappeared in 2011.

Write a 1,500-word story using In Medias Res.

Concept: UN translator, mid-sentence, hears missing brother in headset.

Structure:
1. Opening Scene — the present moment, in the booth, specific phrase she's translating
2. Trigger Flashback — the brother spoke a word she hasn't heard since 2011
3. Rising Action — the 2011 story, one summer, the specific thing that happened
4. Return to Present — the press conference continues, she finishes the sentence
5. Resolution — the next line she speaks, translated, is the answer

Constraints: close third on the translator. Voice: precise, professional, cracking.
Banned: explaining how the brother is in the headset.
Open with: a half-translated sentence, not the brother's voice.
End with: the next sentence, fully translated, no commentary.

Why this works: Two timelines is the constraint that breaks AI out of its "she felt" default — the model has to track present-tense and past-tense at the same time, which forces more careful word choice. The "the next line is the answer" closing line is a structural payoff, not a thematic one.

7. The mistake everyone makes: "show, don't tell"

The most common failure in AI-generated fiction is telling instead of showing: "Sarah was sad" instead of "Sarah put the mug down and didn't pick it up again." This is partly a training corpus issue (the mean of internet fiction includes a lot of "she felt" sentences) and partly a token-prediction issue — the most-likely word after "she" is often "felt." Different models default differently; the 2025 model comparison benchmarks this directly.

The fix is a banned-words list:

  • Forbid any sentence starting with "She felt," "He felt," "They felt," "I felt."
  • Forbid any use of "realized," "understood," "knew that."
  • Add: Every emotion must be shown through one specific physical action, one specific object, or one specific line of dialogue. No abstract emotion words.

A CRAFT Literary essay from March 2025 put it bluntly: AI tools "have amplified the impulse" to skip the sensory work. The fix isn't a different model — it's the prompt. Force the model to do the work of showing, one banned word at a time.

8. How to revise the first draft in 20 minutes

The frameworks above produce a structured draft in 2-3 minutes. The draft will be 70% good. The remaining 30% is revision. A 20-minute revision loop that works for almost any AI-generated short story:

  • 0-5 min — Read aloud: Mark every wince line.
  • 5-10 min — Replace clichés with specific images: "The room was quiet" → "The clock was 20 minutes fast."
  • 10-15 min — Cut every sentence that doesn't advance a beat: If it doesn't change the story, delete it.
  • 15-20 min — Re-check opening and ending: Opening should be the most specific line; ending should be a payoff, not a moral.

This loop is the difference between a draft and a story. Most AI fiction fails not at the prompt stage but at the revision stage — the model produces a 70% draft, and the writer accepts it as 100%.

9. Putting it together

The best prompt for storytelling is a 3-layer prompt: named framework, one-line concept, explicit constraints with a banned-words list. The model will produce a draft that is 70% good, 30% revision work — a realistic baseline for AI-assisted short fiction. Pick one framework, write one prompt, generate one draft, run the 20-minute revision loop. The bottleneck was never the model.

Best Prompt for Translation: Preserve Tone, Not Just Words

When you ask an LLM to "translate this into Indonesian," you get a literal word-swap that loses everything that makes a sentence feel written for a human. The best prompt for translation isn't a translation prompt at all — it's a localization brief that gives the model a glossary, a tone target, an audience, and a definition of done. In this guide, you'll get the 4-part structure we use to turn an idiomatic source text into a target text a native reader would actually trust.

Most translation failures aren't vocabulary failures. They're context failures. A phrase like "we'll circle back" is a meeting-room idiom in English, not a sentence. Translated literally into Indonesian, German, or Japanese, it becomes nonsense. The model isn't broken — your prompt just didn't tell it that you care about tone, register, and cultural fit, not just lexical correspondence.

Why "translate this" is the worst possible prompt

A bare "translate" instruction hands the model three problems at once: tone inference, terminology choice, and idiomatic rendering. It silently picks a register (usually the safest middle), silently picks a terminology policy (usually the first match), and silently picks an idiom strategy (usually literal). You get a draft that reads as "translated by a machine" because the machine had no signal that you wanted anything else.

Translated.com, a translation research firm that runs production LLM pipelines, puts it bluntly: a generic prompt asking a model to "translate this text professionally" is insufficient for any real workflow. The fix is "context engineering" — surrounding the model with glossaries, style guides, and translation memories that anchor the output to a defined target. That's not a luxury. It's the minimum bar for anything that will be read by a real audience.

The 4-part prompt structure that actually works

After testing dozens of variations across English ↔ Indonesian, English ↔ German, and English ↔ Japanese, the structure that consistently produces native-feeling output looks like this:

1. ROLE:   You are a professional [source]→[target] translator specializing in [domain].
        2. SCOPE:  Preserve tone, register, and cultural nuance — not just words.
                   Maintain idioms as natural target-language equivalents; do not literalize.
        3. INPUT:  Source text: <text>
                   Glossary (mandatory terms): <term1> → <translation1>, <term2> → <translation2>
                   Tone: [formal / casual / marketing / academic / etc.]
                   Audience: [description of who will read this]
        4. OUTPUT: Return only the translation. After the translation, list any terms
                   where you deviated from the glossary and why, plus any cultural
                   adaptations you made.

The role line sets the model's voice. The scope line defines what success means — and explicitly forbids the lazy literal strategy. The input block gives it the raw text plus the constraints (glossary, tone, audience). The output block tells it what to deliver and what trade-off notes to surface for your review.

Template 1: Marketing copy with brand voice

Marketing translation breaks the worst when you let the model "smooth it out." Brand voice is the whole asset. Here's a prompt that protects it.

You are a senior EN→ID marketing translator for a B2B SaaS brand whose
        voice is direct, warm, and confident — never hype-y.

        Source text:
        <your landing page paragraph>

        Glossary (use exactly):
        - "workspace" → "ruang kerja" (NOT "tempat kerja")
        - "onboarding" → "penyiapan awal" (NOT "orientasi")
        - "workflow" → "alur kerja"

        Tone: confident, second-person, short sentences.
        Audience: Indonesian operations managers at 50-200 person companies.
        Do not literalize idioms. If a phrase has no natural ID equivalent,
        adapt the meaning while keeping the brand voice.

        Return:
        1. The translation.
        2. A short list of idiom adaptations you made and why.

Notice the glossary lines use "NOT" — that's deliberate. Without it, models default to the first dictionary translation. Spelling out the negative constraint saves a full round-trip.

Template 2: Technical documentation (preserve precision)

Technical translation has the opposite problem: you need precision, not warmth. Keep code identifiers in English, translate comments and UI strings, and never let the model "improve" the technical content.

You are a technical documentation translator. Source EN, target ID.
        Audience: Indonesian software developers.

        Rules:
        - Translate only natural-language text. Keep all code, identifiers,
          filenames, and command-line examples in English.
        - For code comments, translate the meaning but keep the code working.
        - If a UI label is short (≤3 words), match the official product
          Indonesian localization. If unsure, leave a [TODO: ID] marker.
        - Do not "improve" the technical content. If the source is unclear,
          flag it with [SOURCE UNCLEAR: reason] rather than guessing.

        Source:
        <paste the doc section here>

        Output:
        1. The translation with preserved code blocks.
        2. A flagged-issues list at the end.

The "[SOURCE UNCLEAR]" pattern is the key. It tells the model that admitting confusion is better than inventing a plausible-sounding answer — which is exactly how mistranslations enter production.

Template 3: Conversational text (preserve register)

Emails, Slack messages, support tickets — these are the hardest to get right because the entire meaning is in the register. A formal translation of a casual message is, in effect, a different message.

You are translating a casual EN→ID chat message. The relationship
        between the speakers is [colleagues / friends / customer support].

        Preserve the register exactly. If the source uses contractions,
        slang, or emoji, the target must too. If the source is formal
        and polite (e.g., a support reply), keep it polite — don't make
        it chummy.

        Source:
        <the message>

        Return:
        1. The translation.
        2. One sentence explaining how you matched the register.

The "one sentence explaining how you matched the register" is a small but powerful forcing function. It makes the model show its work, which lets you catch register drift in seconds instead of re-reading the whole output.

Template 4: Long-form content (books, articles, reports)

For longer pieces, the trick is to translate in scenes, not paragraphs. Each scene should have its own tone brief, and you should hold the glossary consistent across all of them.

You are translating a long-form [article / chapter / report].
        Source EN, target ID. Domain: [e.g., business, journalism, fiction].

        Master glossary (applies to all scenes):
        - <term1> → <translation1>
        - <term2> → <translation2>

        Current scene: [describe what this section is about and its emotional tone]
        Length: [target word count for this scene — match the source ±10%]

        Source text:
        <paste the scene here>

        Output:
        1. The translation.
        2. A "scene notes" block: any tone choices, idiom adaptations,
           and any terms that didn't fit the glossary and what you used instead.

Translating in scenes with a shared glossary is the same trick novelists use to keep character voice consistent — and it scales. Whether you're doing a 2,000-word blog post or a 60,000-word book, the discipline of a scene-level brief plus a master glossary prevents drift.

The three mistakes that ruin translation prompts

After running hundreds of these prompts, three failure modes show up over and over. All three are fixable.

Mistake 1: One mega-prompt for every document type. A prompt optimized for marketing voice will butcher technical docs. A prompt optimized for technical docs will sound dead in marketing. Use different prompts for different registers. If you find yourself writing "translate this carefully and preserve tone," you've already lost — "preserve tone" means nothing without specifying which tone.

Mistake 2: No negative constraints on the glossary. Just listing "workspace → ruang kerja" isn't enough. Models will sometimes pick a different translation if they think it fits the context better. Add "NOT 'tempat kerja'" explicitly. The extra 10 words save a 20-minute review cycle.

Mistake 3: Skipping the output format block. If you don't tell the model to return its idiom adaptations and term choices, you'll never know where to look when a reviewer flags "this doesn't sound right." Build the audit trail into the prompt itself, and you get free quality control with zero extra effort.

How to evaluate the output (it's not just BLEU)

BLEU score — the old machine-translation metric — counts string overlap with a human reference translation. It works fine for narrow domains where you have many references. It works poorly for creative or idiomatic text, because the "right" translation can be syntactically nothing like the source while still being the right answer.

For LLM-based translation, the field is moving toward COMET and similar learned metrics, which correlate better with human judgment. But the honest answer is: for anything tone-sensitive, you need a native speaker to read the draft and rate it on three axes: accuracy (meaning preserved), naturalness (sounds like a native wrote it), and fitness (fits the audience and domain). A 7-minute human review catches more than any automated metric.

Putting it all together

The reason this works is that you've replaced one vague instruction ("translate this") with a brief a junior translator would actually find useful. The model is a fast, cheap, very literal junior translator. Your job is to brief it like a senior project manager briefs a junior human translator: here's the role, here's the glossary, here's the tone, here's what success looks like, and here's what I want flagged for review.

Once you internalize the 4-part structure — role, scope, input, output — you can adapt it to any domain in five minutes. The templates above are starting points, not endings. The fastest way to make them yours is to translate three real pieces of content with three different domains this week. By the third one, the prompt will feel obvious, and the output will be a draft you can actually send to a reviewer instead of a draft you have to rewrite from scratch.

The best prompt for translation is the one that treats translation as localization, not word-swapping. Give the model a brief, not a sentence, and you'll stop reading outputs that sound like they came from a very polite robot.

Why "best prompt for business plan" is suddenly a 2026 search trend

In 2026, business plans are no longer 50-page documents designed to impress — they are "proof that your startup deserves to exist, scale, and lead," as PrometAI puts it. Investors read between the lines: they evaluate how you think, organize, and anticipate challenges. They have seen thousands of AI-generated plans, so the bar for what passes as "investor-ready" has risen sharply.

Generic output gets rejected before the second paragraph. The good news: a well-designed prompt forces you to feed in those exact inputs — TAM numbers, CAC math, founder credentials — so the AI has no choice but to produce something credible.

The 7 sections every investor-ready plan needs

Before you touch a prompt, lock the structure. The most reliable plans in 2026 follow a 7-section backbone. Memorize this — every prompt template below is just a re-arrangement of the same seven blocks.

  1. Executive Summary — 1 page, written last but placed first. Problem, solution, market size, traction, ask.
  2. Company & Problem — legal structure, mission, the specific pain you solve.
  3. Market Analysis — TAM / SAM / SOM with sources, ICP definition, market trends.
  4. Product & Differentiation — what you build, why it wins, moat.
  5. Go-to-Market & Sales — channels, pricing, CAC, LTV, sales cycle.
  6. Operations & Team — founder bios, org chart, key hires.
  7. Financial Projections — 3-year P&L, assumptions, funding ask, use of funds.

Prompt #1 — The Discovery Prompt (run this FIRST)

Act as a senior strategy consultant from McKinsey with 15 years
helping pre-seed startups raise their first round. You will NOT
write the plan yet. Instead, interview me section by section.

my answers. Do not write any prose. Just ask the questions.

Sections:

2. Company & Problem
3. Market Analysis (TAM/SAM/SOM)
4. Product & Differentiation

Start with Section 1. Wait for my answers before moving on.
If my answer is vague, push back with a follow-up question.

Why this works: it converts the AI into a thinking partner instead of a copywriter. The questions surface assumptions you didn't know you were making — especially around CAC and LTV, where 70% of first-time founders hand-wave.

business plans that successfully raised between $250K and
$10M. Write a complete 7-section business plan using the
answers below. Tone: confident, data-driven, no fluff. Length:
8–10 pages. Use bullet points where density matters. Use
short paragraphs (max 4 sentences).

Company name: [your name]
One-line description: [e.g. "B2B SaaS for HVAC contractors"]
Stage: [pre-idea / prototype / first-revenue / scaling]

SOM (3-year reachable): [$Z]

Estimated CAC: [$X]
Estimated LTV: [$Y]

Distribution channels: [paid ads / outbound / partnerships]
Founder 1: [name, role, 1-line bio, prior exit if any]
Founder 2: [name, role, 1-line bio]
Year-1 revenue target: [$X]

Write all 7 sections. End with a 1-paragraph "Why Now?"
closing argument.

The key trick is the "Use of funds" line. Investors always ask "how will you spend this?" — and 80% of plans fumble it. By forcing percentages in the prompt, you get a clean pie chart on the first pass.

Prompt #3 — The Financial Model Deep-Dive

produce a structured financial model. Format as a markdown
table with these rows per year (Y1, Y2, Y3):

  - Revenue (broken into 3–5 product lines)
  - COGS
  - Gross profit & gross margin %
  - Operating expenses (split: payroll, marketing, R&D, G&A)
  - EBITDA & EBITDA margin %
  - Cash burn
  - Cash on hand (assume starting at funding-ask amount)

Then add a "Key Assumptions" block with 8 numbered bullets
showing the math behind every line. Show your work.

Then add a "Sensitivity Analysis" section: what happens to
runway if CAC is 50% higher than estimated? If LTV is 30%
lower? If we hire 2 more engineers? Give the numbers.

The sensitivity analysis is the part most founders skip — and the part that impresses investors the most. It shows you have stress-tested your own thesis.

Prompt #4 — The Investor-Readability Polish

AI prose tends to be 30% longer than necessary. Investors skim. This prompt compresses without losing substance.

Read the plan above as a partner at Andreessen Horowitz with
8 minutes to spare. Identify the 5 paragraphs that are most
likely to make you stop reading. For each:
  1. Quote the paragraph
  2. Explain why it loses attention
  3. Rewrite it in 2 sentences max, keeping any concrete
     numbers, removing all adjectives.

Then run the same exercise on the Executive Summary: it
must be ≤ 180 words and must contain: problem, solution,
market size, traction, ask. If any of those 5 elements is
missing, flag it.

Finally, replace any instance of the words "leverage",
"synergy", "cutting-edge", "revolutionary", "best-in-class"
with a specific concrete alternative. Print before / after.

This is the secret weapon. It turns "we leverage cutting-edge AI to revolutionize HVAC operations" into "we use GPT-4 to auto-dispatch the 47% of HVAC calls that arrive outside business hours." One is fluff; the other is a fundable sentence.

Even with the best prompt for business plan generation, three failure modes show up in 9 out of 10 first drafts. Recognize them and fix them before you send.

Mistake 1 — Treating the output as final. LivePlan's team warned explicitly: "AI is fantastic for brainstorming, but that doesn't mean you can just cut and paste the results into your business plan." Every number must be sourced. Every assumption must be defensible. The prompt gives you a scaffold; the founder provides the truth.

Mistake 2 — Vague customer definition. If your prompt says "small business owners," the output will be generic. The Prompt #2 template forces you to specify "US HVAC companies with 5–50 techs" — that one change in specificity cascades through every section and makes the plan feel real.

Mistake 3 — Skipping the "Why Now?" closer. Investors always ask why this moment. If the plan doesn't end with a clear answer — a regulatory shift, a new API launch, a post-COVID behavior change, a macro tailwind — it reads as a generic exercise. Reserve 10 minutes at the end of Prompt #2 specifically for this paragraph.

Best Prompt for Product Description: Convert Browsers to Buyers

If you sell anything online, the best prompt for product description is the one that turns a boring 3-bullet spec sheet into a 200-word page that answers the only question a buyer actually has: "What's in it for me?" The good news: the heavy lifting has been done for you. Copywriting frameworks like AIDA, PAS, and FAB have been converting browsers to buyers since 1898 — and they slot cleanly into a ChatGPT prompt. This guide gives you 5 copy-paste templates built on those frameworks, plus the 4 mistakes that make AI product copy sound like AI product copy (and how to fix them in one follow-up prompt).

Why most product descriptions fail

Walk through any Shopify store with 100+ SKUs and you'll see the same five phrases recycled: "premium quality", "high-performance", "designed for everyday use", "perfect for any occasion", "a must-have." They're not wrong. They're just empty. WordStream's roundup of common copywriting mistakes nails it: copywriters "craft content in a way that makes sense to them, not the audience they need to engage." A spec sheet tells you what the product is. A buyer wants to know what it does for them in their life — that's the entire job.

The 5 frameworks worth memorising are AIDA (Attention → Interest → Desire → Action), PAS (Problem → Agitate → Solution), FAB (Feature → Advantage → Benefit), PASTOR (Problem → Amplify → Story → Testimony → Offer → Response), and 4Ps (Picture → Promise → Prove → Push). You don't need all of them. Pick the one that matches the page length. A landing page wants PAS or AIDA. A product detail page (PDP) wants FAB. A category tile wants 4Ps in two sentences.

The anatomy of a conversion-focused description

Every good product description, no matter the framework, has the same four beats:

  1. The hook. A sentence that names the buyer's pain or desired outcome. Not a tagline — a problem statement.
  2. The bridge. One or two sentences of features translated into advantages ("5000 mAh battery" → "lasts a full weekend off-grid").
  3. The benefit cascade. 2-4 short paragraphs or bullets answering "so what?" for each feature. This is where most AI copy skimps.
  4. The call to action. A specific next step — not "buy now" but "add to cart" or "reserve your pair" or "start your 30-day trial".

Your prompt must explicitly request all four beats. If you skip the hook, the output reads like a brochure. If you skip the benefit cascade, the output reads like a spec sheet. The templates below bake all four beats into the prompt so you don't have to remember them.

Template 1: The FAB long description (200+ words)

Use this for your hero PDP. FAB is the workhorse of ecommerce — Feature (what it is), Advantage (what it does), Benefit (what that means for the buyer). The prompt below turns a 4-bullet spec list into a 250-word narrative. Pair it with our marketing prompt library for cross-sell and email follow-ups.

Role: You are an ecommerce copywriter who writes in the style of
Allbirds and Glossier — concrete, sensory, no hype words.

Product: {product name}
Category: {category}
Audience: {who is the buyer, e.g. "remote workers in their 30s"}
Key specs: {bullet list of 3-5 raw features}
Price point: {budget / mid / premium}

Write a 250-word product description using the FAB framework
(Feature → Advantage → Benefit). Open with a 1-sentence hook that
names the buyer's pain. Then for each spec, write 1-2 sentences
that move from feature to advantage to benefit. Close with a
specific call to action (e.g. "Add to cart" or "Pick your size").

Rules:
- No hype words: avoid "premium", "high-quality", "perfect",
  "ultimate", "must-have", "luxurious".
- Replace each feature with at least one sensory detail
  (texture, weight, sound, time saved, money saved).
- Use second person ("you"), not third ("the customer").
- Do not start with the product name.
- Output: one paragraph per beat, no bullet points.

Template 2: The PAS short description (60-80 words)

Use this for category tiles, ad copy, and the top of an email. PAS (Problem → Agitate → Solution) is the shortest framework that still converts because it forces the writer to articulate the pain before pitching the fix. The "Agitate" step is the one most prompts skip — and it's the one that does the selling.

Write a 70-word product blurb in the PAS framework.

Product: {product name}
What it replaces or fixes: {the old way}

Structure:
- Problem (1 sentence): name the specific frustration the buyer
  has before they find this product.
- Agitate (1-2 sentences): describe the cost of that frustration
  in time, money, or emotion. Make it concrete.
- Solution (2-3 sentences): introduce the product as the cleanest
  fix. Lead with the benefit, not the feature.
- Close (1 sentence): a specific next step.

Tone: conversational, second person, no exclamation marks.

Template 3: The bullet-stack quick description (5-7 bullets)

Use this for the spec section under the main PDP copy, or for Amazon listings where shoppers scan rather than read. Each bullet follows a "verb + benefit + detail" pattern so it scans as a benefit, not as a feature.

Write 6 product bullets. Each bullet must be 12-18 words and
follow the pattern: [verb-led action] + [buyer-facing benefit] +
[concrete detail or number].

Product: {product name}
Specs to cover: {list of 4-6 raw features}
Audience: {one-line persona}

Rules:
- Start each bullet with a verb, not "Featuring" or "Includes".

Common mistakes that make AI copy sound like AI copy

You can paste any of the templates above into ChatGPT and get a usable first draft in 30 seconds. You can also get generic mush if you skip these four guardrails. Best Prompt for Cover Letter: Get Past the ATS Robot

If you have ever pasted a job description into ChatGPT, hit "generate", and submitted whatever came out without editing, you are not alone — and you are almost certainly not getting callbacks. According to a 2026 TopResume survey, 67% of hiring managers can identify AI-generated cover letters, and 54% view them negatively. The recruiter reading your letter is doing the same pattern-matching that a ChatGPT cover letter copilot does: every applicant who opened with "I am excited to apply for the [Job Title] position at [Company]" gets mentally filed under "low effort" and moved past. Meanwhile, 75% of resumes are rejected by ATS software before a human ever sees them (Jobscan, 2023), so even a generic letter is competing with 200+ applications filtered down to a five-callback pile.

The best prompt for cover letter writing is not the one that produces the longest output. It is the one that turns a one-line job description and a thin resume into a 3-paragraph letter that survives ATS screening, passes the 7-second recruiter scan, and gets you into the phone-screen pile. This guide gives you a four-part framework, four copy-paste templates (entry-level, mid-career, career-changer, executive), and the three mistakes that turn a 10-second prompt into a rejection email.

Why Most ChatGPT Cover Letters Get Ignored

The problem is not that the model writes badly. The problem is the prompt. According to Cover Letter Copilot's 2026 analysis of 10,000 job applications, cover letters created with basic ChatGPT prompts had a 23% lower callback rate than those written with strategic prompting. The same survey found that 81.6% of recruiters have encountered AI-written cover letters in the wild, and only 3.3% were unsure whether a letter was AI-generated — they pattern-match the generic phrases instantly.

Three structural failures cause the drop. First, the prompt gives the model no audience anchor, so it defaults to the safest possible tone: enthusiastic, vague, and indistinguishable from 200 other applicants. Second, the prompt asks for everything at once — opening, body, close, metrics, "why this company" — and the model has to pick what to skip. Third, the prompt has no output constraint, so you get a 600-word essay when the recruiter wanted a 220-word letter. The fix is structural, not stylistic.

The 4-Part Framework: A.R.C.S.

A.R.C.S. stands for Audience, Role, Context, Shape. It is the minimum viable brief for any cover letter, and it works with ChatGPT, Claude, Gemini, and Copilot. Each part serves a specific failure mode:

  • Audience — tell the model who reads this (recruiter vs hiring manager) and what they care about. Prevents the "I am excited" generic enthusiasm.
  • Role — state the job title, seniority, and the single biggest problem the hire is meant to solve. Prevents the "this could be any job" feeling.
  • Context — paste the job description AND your resume, plus 2-3 quantified achievements. Prevents the model from inventing metrics.
  • Shape — specify length, paragraph count, tone, and the one thing you want the reader to remember. Prevents the 600-word wall of text.

Skip any one of these and the model falls back to defaults. With all four, you get a first draft that is 80% ready to send — and that is the entire point. The remaining 20% is yours: one company-specific sentence, one metric you actually have, and one proofreading pass.

Executive letters are the easiest to get wrong with a generic prompt because the model's default tone is "candidate to gatekeeper" — deferential, hedge-heavy, and full of enthusiasm. The "tone: peer to peer" instruction in Template 4 overrides that default. Combined with the "30 seconds" audience framing and the P&L metric requirement, it produces a letter that reads as if it was written by someone who has been in the room, not someone who wants to be in the room. 3 Mistakes to Avoid

1. The "Write me a cover letter" prompt. This is the equivalent of asking a stranger to introduce you at a networking event with no context — you get the safest possible version, which is the version 200 other people also got. The Cover Letter Copilot survey found that 67% of hiring managers identify AI-generated letters on tone alone, and the most reliable signal is generic enthusiasm ("I am excited to apply", "I believe I would be a great fit") with no specifics. The fix is the A.R.C.S. framework: every input you skip is a dimension the model has to invent, and what it invents is always generic.

2. Pasting the job description without your resume. The model can only connect your experience to the role's requirements if it knows what your experience is. Without your resume, it falls back to placeholder phrases like "my background in [field]" — which is a tell. The fix is to always paste both the JD and your resume, plus 2-3 quantified achievements, in the same prompt. If you do not have metrics, write down the roughest possible number ("managed roughly 10 client accounts", "worked on a project with about 30 stakeholders") — the model is much better at anchoring a real number than it is at inventing one.

3. Sending the first draft. The first draft is a draft. Plan to edit 40-60% of it — add one company-specific sentence (cite a recent news item, product launch, or initiative), swap in one real metric, and read it aloud once. The reading-aloud step catches the awkwardness that pure proofreading misses: sentences that are grammatically correct but rhythmically off, the kind of phrasing a model produces when it is over-fitting to formal cover-letter templates. The recruiter spends 7.4 seconds on the initial scan (Ladders, 2018); a letter that reads smoothly in 7.4 seconds is the only one that gets the next 60.

Put It All Together

The full A.R.C.S. pipeline runs in this order:

  1. JD + Resume Ingest — paste both into the prompt, plus 2-3 achievements with metrics. This is the "context" layer.
  2. Template Selection — pick Template 1, 2, 3, or 4 based on your seniority and situation. The template's "audience" and "shape" lines do most of the structural work.
  3. First Draft — generate, then read aloud. Replace any sentence that does not pass the "could only have been written for this company" test.
  4. Final Pass — one company-specific sentence, one real metric, one proofread for typos. Total time: 4-6 minutes per application.

For most job applications, the entire pipeline takes under 6 minutes per role — versus the 30-45 minutes most candidates spend on a "from-scratch" cover letter that still reads generic. The output passes ATS keyword matching, survives the 7-second recruiter scan, and reads as if it was written by a person who actually wanted this specific job at this specific company. That is what makes a prompt the best prompt for cover letter — not cleverness, but structure. What "SEO Prompt" Actually Means in 2026

An "SEO prompt" is not a magic phrase you paste into ChatGPT that guarantees a #1 ranking. No prompt does that, and any prompt that claims to is selling the same snake oil Google cracked down on with the August 2024 core update ("created just for SEO purposes" was the wording in Google's official guidance). An SEO prompt is a structured instruction that gets the LLM to produce content matching the four signals Google's ranking system uses to decide whether a page deserves a top slot — and now also matches the three extra signals Google's AI Overview citation layer uses to decide whether to quote your page inside the AI-generated summary at the top of the SERP.

Those four classical ranking signals are: search intent match (does the page answer the question the searcher actually typed?), topical depth (does it cover the sub-questions a knowledgeable reader would expect?), E-E-A-T demonstration (Experience, Expertise, Authoritativeness, Trustworthiness), and technical SEO hygiene (crawlable, fast, schema-marked, internal-linked). The three AI Overview citation signals add: structured quotability (are the answers in clean extractable blocks — definitions, lists, tables — rather than buried in prose?), freshness (does the page show a visible last-updated date and recent statistics?), and entity clarity (does the page unambiguously establish who, what, where, and how?). A prompt that hits all seven will rank; a prompt that hits only the first four will rank in classical results but get skipped by the AI Overview layer — and in 2026, that is half your potential clicks.

The fix is not to avoid AI Overviews (you cannot), it is to be the source the AI Overview cites. A page that AI Overviews quote inside the summary box still gets branded visibility and a smaller but still-meaningful click stream; a page that AI Overviews skip gets nothing.

The 5-Part SEO Prompt Framework (S.E.A.R.C.H.)

Every SEO prompt that produces a page that ranks follows the same five-part structure. Skip any one of them and the model fills the gap with training-data default — which is a 2,000-word, vaguely-related, helpful-assistant-voiced article that neither ranks nor gets cited. The acronym is S.E.A.R.C.H.: Subject, Entity, Angle, Reader, Constraints, Hit-list. (The sixth "H" is the AI-Overview-citation brief, which we add below.)

  1. S — Subject & Search Intent: the exact keyword + the intent category (informational, commercial, transactional, navigational) + the format Google rewards for that intent (how-to, listicle, comparison, definition, review).
  2. E — Entity & E-E-A-T Signals: who is publishing this, what credentials they have, what first-hand experience they bring, and which authoritative sources they will cite. This is the section most prompts skip and the one Google's helpful-content classifier weights most heavily.
  3. A — Angle & Differentiation: the unique take, data point, or contrarian position that makes this article not a paraphrase of the top 10 existing results. Without this, the model writes a generic "10 tips" article that adds zero new information.
  4. R — Reader & Reading Level: who is reading, what they already know, what jargon is OK, and what the desired reading-level grade (Flesch 60–70 for most web content).
  5. C — Constraints & Output Contract: word count, heading depth (H2 / H3 / H4), number of internal/external links, tone, and the exact list of required sections (TL;DR, FAQ, key takeaways, comparison table).
  6. H — Hit-list for AI Overview Citation: the 3–5 extractable blocks (definitions, numbered steps, comparison tables, statistics with citations) the model must include so the AI Overview citation layer has clean quotable material.

The 3 Mistakes That Get AI SEO Content Filtered Out

These three mistakes account for roughly 80% of the AI-generated SEO articles that never rank. The first is the most common.

Mistake 1: No Entity, No E-E-A-T. The single biggest reason AI-generated SEO content gets filtered out of both classical ranking and AI Overview citation is that it has no demonstrable author entity, no first-hand experience, no source citations, and no obvious expertise signal. Google's helpful-content classifier is trained to spot "content created just for SEO purposes" — and the marker it uses is the absence of any of the E-E-A-T signals. The fix is the ENTITY block in the master prompt: name the author, list their credentials, declare the first-hand experience, and cite at least 3 authoritative sources. Without this block, the model writes the kind of generic "10 tips" article that gets deindexed in the next core update.

Mistake 2: Keyword stuffing in the prompt itself. New SEO users often "stuff" the target keyword 5–10 times in the prompt, thinking it will make the output rank better. It does the opposite — the model produces an output where the keyword density is unnatural, which the helpful-content classifier reads as a manipulation signal. The correct pattern is to mention the target keyword exactly once in the SUBJECT block, and then describe the search intent in natural language. The model's output will naturally include the keyword 3–7 times in 2,000 words, which is the density Google's helpful-content classifier rewards.

Mistake 3: No AI Overview quotable blocks. In 2026, a 2,000-word SEO article without a clean definition block, a numbered step list, a comparison table, and 2–3 cited statistics will rank in classical results but get skipped by the AI Overview citation layer — losing half your potential CTR. The HIT-LIST block in the master prompt exists to fix exactly this. Every AI Overview citation begins with the model extracting a clean, structured block of text from a source page — and if your page does not have one, the AI Overview cannot cite it.

Best Prompt for YouTube Script: Hook + Payoff in 8 Minutes

Writing a best prompt for YouTube script isn't about asking an AI to "write me a video." That's the fastest way to get 800 words of beige copy that loses viewers in five seconds. The real best prompt for YouTube script work is structural: it forces the model to commit to a hook pattern, a payoff, and a CTA before it ever writes a sentence of body. Without that scaffolding, even ChatGPT, Claude, and Gemini default to generic intros that read like a Wikipedia summary.

YouTube's algorithm has been ruthlessly clear about what it rewards: average view duration, click-through rate, and audience retention curve. As of 2026, the average YouTube video holds viewers for only about 41.9% of its runtime, and Shorts lose 40–60% of their audience before the 15-second mark. That means the first 5–15 seconds of every video do more work than the next five minutes combined. A good script prompt doesn't just give you words — it gives you a structure the algorithm can read.

Why most "best prompt for YouTube script" lists fail

Most prompt libraries online are written for bloggers, not creators. They suggest things like "write a YouTube script about productivity" and call it a day. That kind of prompt produces generic intros: "Hey guys, welcome back to my channel. Today we're going to talk about…" — which the ClipHorizon team correctly calls "permission to swipe." The viewer hasn't been given a reason to stay; they've been given an exit ramp.

The other common failure mode is treating the script as one monolithic block. A real YouTube video has at least four distinct jobs — hook, setup, value, close — and each one needs a different prompt or at least a different instruction set. If you give the model one prompt and ask for "the whole script," you'll get a script that's optimized for none of the parts. The strongest prompts chunk the work: one prompt per section, chained together with explicit handoffs.

The Hook–Promise–Payoff framework

The CaptainHook video breakdown nails the framework that every high-retention script shares: pattern interrupt → promise → payoff. A pattern interrupt is the unusual opening — a close-up of something dramatic, a counter-intuitive claim, a question the viewer didn't expect. The promise tells them why staying will give them value. The payoff is the part of the video that makes them feel the promise was earned.

Vague promises create doubt. Overpromising with a weak payoff creates churn. The prompt needs to force the model to articulate all three explicitly, in that order, before any body content is written. If the model can't fill in "what's the payoff?" in one sentence, the script isn't ready to draft.

You are a viral video copywriter. The video topic is [TOPIC].
Target viewer: [AUDIENCE: e.g., "beginner Python devs, 25-40"].

Step 1 — Hook (≤10 seconds spoken):
Write three variations of an opening hook that uses either
(a) a counter-intuitive claim, (b) a specific number, or
(c) a knowledge gap the viewer wants closed. Each hook ≤ 18 words.

Step 2 — Promise (≤8 seconds spoken):
Write one sentence naming the three concrete things the viewer
will be able to DO or UNDERSTAND after watching. No vague
benefits. Each benefit must be testable.

Step 3 — Payoff preview (≤6 seconds spoken):
Write a single line that teases the strongest moment of the video
without spoiling it. This becomes the B-roll or cutaway moment
at 0:08–0:14.

Output as labeled blocks: HOOK 1/2/3, PROMISE, PAYOFF.

After you've approved those three blocks, you feed them back into the body prompt. This is the "prompt chain" pattern: a first prompt that does strategy, a second that does execution. It mirrors how an actual screenwriter works — outline first, draft second.

Long-form vs. Shorts: two different prompts

A 12-minute YouTube essay and a 45-second Short are scripted with completely different logics. For long-form, the hook has to survive for 30 seconds because you have room for context. For Shorts, the entire value core is 30 seconds long, so the hook is the brand.

For Shorts, use the 4-part structure documented by the ClipHorizon team: Hook (0–3s) → Setup (3–8s) → Value Core (8–40s) → Close (40–end). The Value Core should be exactly one mechanism, one contrast, or one reframe — not four. If you have four points, you have four Shorts.

Write a 45-second YouTube Short script on [TOPIC].
Tone: [e.g., direct, slightly opinionated, no "hey guys"].
Format STRICTLY:

HOOK (≤3s, ≤10 words): a single line that creates a knowledge
gap OR triggers emotion strong enough to stop the thumb.
Forbidden openers: "hey guys", "today we're going to",
"so I wanted to talk about".

SETUP (3–8s, ≤15 words): one sentence validating the hook and
framing what's coming. No backstory.

VALUE CORE (8–40s, ≤80 words): exactly ONE of these:
- Mechanism: why X causes Y
- Contrast: what most people do vs. what high performers do
- Reframe: the thing everyone thinks is the problem isn't
Keep sentences ≤12 words. Insert [PAUSE] markers every 8–10
words for the editor.

CLOSE (last 3–5s, ≤15 words): resolve what the hook opened.
If the hook promised "the reason your Shorts die at 10s,"
the close names that reason.

Output as four labeled blocks.

For long-form, swap in the Hook–Pain Point–Promise opener from Prompt Sigma: hook, single empathetic sentence acknowledging the viewer's current struggle, then a concrete promise of the three biggest takeaways. That opener buys you roughly 20 seconds of attention — enough to get into the meat.

The four prompt templates

Below are four copy-paste templates you can use as-is. Each one assumes you'll do a research pass first — gathering outlier scripts, real audience pain points, and your own voice samples. As OutlierKit's Aditi put it: "ChatGPT scripts only sound AI-generated when the prompt is generic — feed real niche data and the output gets sharper." Replace the bracketed slots with specifics from your niche, not generic words.

Template 1 — Tutorial Script (8–12 min):

Write a YouTube script for an 8–12 minute tutorial video.

Topic: [SPECIFIC TOPIC, e.g., "how to use Claude's tool-use API"]
Skill level of viewer: [e.g., "intermediate Python devs"]
One thing they'll be able to do after: [VERB-PHRASE]

Structure:
- Cold open (0:00–0:20): demo the final result first, no intro
- Context (0:20–0:45): one paragraph on why this matters now
- Step 1 (0:45–3:00): walk through, narration in second person
- Step 2 (3:00–5:30): walk through, narrate tradeoffs
- Step 3 (5:30–8:00): walk through, narrate common mistakes
- Recap (8:00–9:00): three bullets, no fluff
- CTA (9:00–9:30): specific next video, not "subscribe"

Constraints:
- Spoken word count: 1,100–1,400 (≈150 wpm target)
- Each paragraph ≤ 3 sentences on screen
- No "in this video" or "let's get started"

Template 2 — Story-driven video (10–15 min):

Write a story-driven YouTube script using the 5-part structure:
Hook, Setup, Conflict, Turning Point, Resolution.

True story / case study: [SUBJECT]
Emotional core: [e.g., "an underdog founder who almost quit"]
Target arc length: 12 minutes spoken
Viewer's takeaway (one line): [e.g., "constraints force clarity"]

Open with the most dramatic moment (mid-action), not the
backstory. Spend 40–50% of total runtime on conflict and
obstacles. End with the emotional impact, not just facts.

For each section, output: TIME, NARRATION, VISUAL.

Template 3 — Comparison / "X vs Y" video (6–9 min):

Write a comparison YouTube script.

Tool A: [NAME]  | Tool B: [NAME]
Use case: [SPECIFIC SCENARIO]
Viewer's decision: [WHAT THEY'RE CHOOSING BETWEEN]

Required sections:
- Cold open (0:00–0:25): state the conclusion, then explain why
- Side-by-side demo (0:25–3:00): same task on both, screen-recorded
- 3-point comparison (3:00–6:00): speed, quality, cost — show, don't tell
- Verdict (6:00–7:30): pick one, justify in ≤ 60 words
- CTA (7:30–8:00): "if you're deciding between X and Y for [SCENARIO],
  here's the next video to watch"

Constraints:
- Neutral until the verdict; no strawmanning
- Show timestamps and on-screen labels for the demo
- Total spoken: 950–1,200 words

Template 4 — Listicle (8–10 min):

Write a listicle YouTube script. List of N: [e.g., "7 Claude
prompting mistakes I made in my first month"].

Required structure:
- Cold open (0:00–0:25): name the most painful mistake first
- Why this list matters (0:25–0:50): the cost of not fixing these
- Items 1–N (each ~60s): mistake → why it hurts → fix → example
- Recap (last 60s): the one fix to make today
- CTA (last 15s): pin a comment with the full checklist link

Constraints:
- Each item must have a concrete example, not generic advice
- No "tip #5 will blow your mind" hype language
- Spoken: 1,150–1,400 words
- On-screen: numbered lower-third for every item

The common mistake: one prompt for the whole script

The biggest mistake creators make is using one mega-prompt for the entire video. "Write me a 10-minute script about X with a strong hook and a CTA" sounds efficient. It isn't. The model has to juggle hook, structure, voice, length, CTA, and tone in one pass, and it optimizes for whichever constraint you forgot to weight. Usually that's length — you get a 1,800-word script that's well-structured but reads like an essay.

The fix is the chain pattern: research → strategy → draft → de-AI-ify. The OutlierKit guide documents this as the workflow used by full-time YouTubers running faceless channels. A first prompt asks for the Hook–Promise–Payoff blocks only. A second prompt takes those blocks and drafts the body. A third prompt takes the body and strips the AI-isms: "however," "moreover," "in conclusion," "it's worth noting that." A fourth prompt rewrites the close in your own voice, using a 200-word sample you pasted in.

Each prompt does one job. Each one is auditable. If a section is weak, you re-run just that prompt with a sharper instruction — you don't throw away 1,200 words and start over.

How to feed the prompt real niche data

The OutlierKit guide is blunt: a prompt that says [NICHE] works when you write "budget cooking creators in Jakarta" and fails when you write "food." The model has no idea what's working in your niche this week. It pattern-matches against the general internet. For creators scripting with Claude instead of ChatGPT, the 9 Claude prompting tips cover the model-specific differences. To get scripts that read like a niche expert wrote them, the same logic that powers any prompt engineering workflow. feed the model:

  • 3–5 outlier transcripts from competitors' top videos (drop them into the prompt as "examples of tone and pacing")
  • Real audience comments — copy 30 comments from your last video so the model sees the actual objections and vocabulary
  • One paragraph of your own voice — past the spoken intro of a previous video so the model can mimic sentence length and rhythm
  • One specific contrarian take — the model is great at defending a position it's been handed

That input transforms a generic "best prompt for YouTube script" into a niche-tuned one. You'll still edit the draft — always — but the first revision will be much closer to publishable.

Editing the draft: the de-AI pass

Even with great prompts, AI drafts have tells. The most common ones in 2026: "Let's dive in," "It's worth noting," "In today's video," "Whether you're a beginner or an expert," and the dreaded "Hope this helps!" The fix is a final pass prompt that scans for these and rewrites them in a register you specify. The same logic shows up in the prompt engineering workflow.

Read the script below. Replace every instance of these phrases
with nothing (cut them entirely):
- "let's dive in"
- "it's worth noting"
- "in today's video"
- "whether you're a beginner or an expert"
- "hope this helps"
- "with that said"
- "moreover", "furthermore", "additionally"

Also flag any sentence > 22 words and shorten it to ≤ 14 words
while keeping the meaning. Output the cleaned script with
[CHANGED] markers next to every line you modified.

Run that, then read the script aloud. The 150-wpm target means roughly 1,000–1,300 spoken words for an 8-minute video. If you're over, cut the recap section before you cut the value core. If you're under, the hook probably needs to do more work — extend the cold open, not the body. Pair this with a storytelling arc and you get videos like the ones covered in the storytelling prompt guide.

Putting it all together

The best prompt for YouTube script work isn't a single magic prompt. It's a chain: research → strategy blocks → body draft → de-AI pass → voice rewrite. Each prompt in the chain does one job, and each one is auditable. That structure is what separates scripts that hold the 41.9% average view duration from scripts that don't.

Start with the Hook–Promise–Payoff prompt above. Approve those three blocks before you ever draft the body. Use the 4-part Shorts prompt for any video under 60 seconds. Pick one of the four long-form templates — tutorial, story, comparison, or listicle — and feed it real niche data. End every script with a de-AI pass. Read it aloud once before you record.
